Section 2 · Method

方法详解：自动化控制 + 局部流编辑

两个阶段：Stage 1 把一条指令自动变成「可视化引导图 + 精修 3D mask」；Stage 2 在预训练模型原生空间里用 DFG + TPG 完成局部编辑。

① Stage 1 · VLM 驱动的编辑控制构建

1

视角选择 + 引导图

Qwen3-VL-8B 多视角理解资产、解析目标部件（含"左边的柱子"等关系指令）、判定 5 类操作、排序视角 → 选中最佳视角 → FLUX.1 Kontext 生成编辑引导图 I_edit

2

P3-SAM 部件分解

原生 3D 分割出语义部件（持久 ID + 颜色），多视角渲染后 VLM 依据指令选出目标部件 ID 集合 → 初始 mask M⁰

3

多模型边界精修

PartField/S2AM3D 的层次/多粒度分割补充：纯度(≥0.6)筛选 → 贪心最大化面积加权 F1 → 等权三模型共识（≥2/3 支持为可靠前景）

4

法向感知图优化

网格面图 + ICM 求解：平滑表面标签一致、法向突跳处允许翻转 → 边界停在几何部件交界处；连通性过滤 + 小碎片剔除 + 小孔填充

5

操作感知体积化

删除=+1 圈面环；替换/几何修改=+4 圈邻域；外观修改=窄边界；新增=锚点周围未占用稀疏坐标 → 最终 mask M_edit / M_keep

所有分割结果先映射到公共表面点集（10 万采样点，按最近邻），再统一到模型原生稀疏坐标——避免不同模型重网格带来的面索引不一致。

② Stage 2 · 局部 3D Flow 编辑（DFG + TPG）

DFG · 差分流引导（改哪里）

沿用 FlowEdit 的免反转原则：编辑状态初始化为源 latent z_edit = x_src；每步计算差分速度 Δv_t = v_θ(z_tgt, c_edit) − v_θ(z_src, c_src)（4 个噪声样本求期望，CFG scale 5.0，25 步）；更新 z_edit ← z_edit + γ·Δt·S_edit ⊙ Δv_t——mask 把结构更新严格锁进目标区域。

25 步DFG 流步数
×4每步差分速度噪声平均
5.0源/目标 CFG scale

TPG · 轨迹保持引导（护哪里）

关键洞察：DFG 只管结构更新，后续特征生成阶段目标条件全局施加，非目标区域仍会漂移。TPG 每步估计终端干净态 x̂_0,t = z_tgt − t·v_θ(...)，定义保持损失 L_pres = ‖S_keep ⊙ (x̂_0,t − x_src)‖²（12 步，λ=12），用梯度软校正 z_edit ← z_edit − λ·∇L_pres 把保留区轨迹拉回源状态。

12 步TPG 特征生成步数
λ=12保持强度（20 会过约束）
软校正不替换中间特征
🔑 TPG vs 硬替换（论文的核心方法主张）：Nano3D/VoxHammer 把保留区特征直接替换回源值——但源特征与演化中的编辑区不兼容：羽毛替换案例中帽子几何碎裂、柱子替换案例中柜子纹理污染。TPG 的梯度软校正不覆盖中间特征，保持编辑区与保留区的连续性，是"软约束替代硬替换"的方法级改进。

③ EditFlow-Bench：补充评测基准

100 个源资产

GSO 真实扫描 30 + ABO 商品 30 + TRELLIS.2 生成 20 + Hunyuan3D 2.1 生成 20 —— 覆盖扫描/人工/生成三类来源，避免依赖单一资产源。

200 个编辑案例

自动 mask + 人工验收

3.4 工程细节 & 与 Buffalo 的对照

工程配置

骨干 TRELLIS.2（默认）+ TRELLIS（公平对比）；Qwen3-VL-8B + FLUX.1 Kontext [dev]；单张 A800（80GB）< 1 分钟/资产（含 DFG + TPG + 最终生成，不含 VLM/分割/引导图前置耗时）。

与 Buffalo（Nano3D-v2）的对照阅读

Nano3D-v2 用硬体素替换规模化造编辑数据 → 训练出会编辑的模型（把能力训进模型）；EditFlow3D 用软轨迹校正在推理时现场编辑（用模型的能力）。"如何保住未编辑区域"的两种答案恰好互补。

⚖️ 评注：优点是全流程自动化 + 软约束机制 + 实验扎实（双骨干/双基准/5 类消融/40 人用户研究/λ 灵敏度）。可商榷处：① EditFlow-Bench 的人工二元验收虽避免手修，仍隐含选择效应；② 编辑质量受骨干与 2D 引导图质量双重制约；③ "<1 分钟"未计入控制构建前置耗时。
Section 4 · Discussion

讨论：区域确定、应用场景、变体与材质编辑边界

基于方案本身的延伸思考：编辑区域是如何被确定的、文本/图像驱动下有哪些应用场景与变体、以及材质编辑对基础模型能力的真实依赖。

4.1 编辑区域如何确定：三层级联机制

"改哪里"由三个粒度的级联决定，每层回答不同的问题：

层级机制回答的问题输出
L1 语义选择Qwen3-VL-8B 解析指令（名词短语→物理部件，如"左边的柱子"）+ 判定 5 类操作；P3-SAM 原生 3D 分割出带持久 ID 的语义部件，多视角渲染后 VLM 选出目标部件 ID 集合改哪个语义部件初始 mask M⁰
L2 边界精修PartField/S2AM3D 多粒度分割补充 → 纯度筛选(≥0.6) → 贪心最大 F1 → 等权三模型共识(≥2/3 支持=可靠前景) → 法向感知网格图优化(ICM) → 连通性过滤 + 碎片剔除 + 小孔填充边界停在几何部件交界处的哪条线精修表面 mask M_ref
L3 操作感知体积化按操作扩张：删除+1 圈面环 / 替换+几何修改+4 圈邻域 / 外观修改窄边界 / 新增=锚点周围未占用稀疏坐标允许生成器在多大体积内动手最终 M_edit / M_keep

三个设计哲学

  • 多模型共识防"一言堂"：任一分割模型的错误不能单独覆盖语义目标——P3-SAM 给语义身份，辅助模型只纠边界，"不确定区"被显式暴露给图优化处理
  • 法向感知让边界停在物理关节处：图优化在平滑表面强制标签一致、法向突跳处允许翻转
  • mask ≠ 编辑区，操作类型决定裕量：替换/几何修改给 4 圈邻域（可改轮廓与附着），删除只给 1 圈——区域大小本身是操作语义的函数

关键认知与已知局限

区域有"空间权威"与"视觉权威"两层：3D mask 是空间权威，锚点视角 + 引导图是视觉权威——视角选错会连带引导图错，即使 mask 再准，DFG 的差分速度也源自该视角的 2D 编辑结果。

局限：细薄/重度遮挡部件上分割误差会传播；mask 内部可能夹带非目标区；EditFlow-Bench 的 mask 虽自动构建但仍有人工二元验收，隐含选择效应。

4.3 图生 3D 变体（弱化文本控制）

文本退化后，难点从"语义理解"转移到"视觉对应 + 参考外观注入"——链路依旧成立，但每个环节长出新的变体。

图像驱动的应用场景

  • 部件换件（Exemplar Swap）：参考图（轮毂/枪托/翅膀）→ 资产对应部件替换——3D 版"部件 faceswap"
  • 材质/纹理迁移：参考图定外观（木纹/皮革/大理石），只动 PBR 属性不动几何
  • 照片驱动修复：拍真实物体照片 → 资产改到照片状态（文物修复/电商）
  • 数字人换装：上传服装图 → 换装（电商试衣，商业价值最直接）
  • 风格迁移到资产：油画/赛博朋克风格图 → 全资产外观（mask 全开）
  • 场景物体替换：照片驱动的 3DGS 场景编辑

技术变体（围绕"对应 + 注入"）

  • 视觉对应替代文本 grounding：DINO/PartField dense correspondence，参考部件 ↔ 资产部件自动对应
  • 参考图直投 c_edit：跳过 FLUX 2D 编辑环节，参考部件图像直接编码为 DFG 目标条件——省掉 2D 编辑误差，最自然的图像版简化
  • 视角自动对齐：参考图视角未知时先估相对位姿
  • 差异驱动定位：参考图与源渲染的差异图直接驱动 mask 构建
  • 外观-几何解耦双 mask：表面属性 mask 与体积几何 mask 分离，图像条件可只驱动其一
  • 图像驱动蒸馏：自举生成"部件 swap"配对 → 训练一次前馈 image-driven editor

4.4 材质编辑是否需要基础模型支持目标材质生成？

⚖️ 结论先行：需要，而且是硬性前提——但"需要"可拆成三个不同强度的层面。编辑的执行者是基础生成模型的 denoiser：DFG 用 v_θ(z_tgt, c_edit) − v_θ(z_src, c_src) 的差驱动编辑，目标材质必须能被该 denoiser 生成出来，否则引导图再漂亮，3D latent 也"长不出来"。
层面要求反例说明
① 表示覆盖基础模型 latent 必须承载目标材质的属性通道（天花板）TRELLIS.2 O-Voxel 仅 6 通道 PBR（basecolor/metallic/roughness/alpha），没有 transmission/thickness/ior 通道 → 薄壁透射/体积吸收在 latent 里没有坐标，无法原生表达
② 生成先验denoiser 必须在目标材质域的训练分布内见过足够样本（现实线）材质 SC-VAE 只过滤标准 metallic-roughness 工作流（~35 万资产）训练 → 薄膜干涉/色散/各向异性等 OOD 材质大概率退化为近似
③ 2D→3D 提升保真两级能力栈：FLUX 前端（2D 先"生成"目标材质）+ 3D 后端（材质身份无损提升进 latent）（实际分）2D 编辑错一步 3D 跟着错；几何-材质联合生成比纯材质更脆

三个推论

  • 外观编辑比几何+材质联合编辑宽容得多：TRELLIS.2 材质 SC-VAE 是解耦的（材质分支以形状子分结构为条件）——只改材质时 TPG 锁死几何轨迹，对先验要求最低
  • 材质编辑质量 = 表示属性覆盖 ∩ 生成先验：想编辑 transmission 类材质，光换引导图没用，得先让表示带上这些属性（如给 O-Voxel 加通道）
  • "需要支持"≠"必须端到端生成"：图生 3D 版可"参考图直投 c_edit"借用材质身份——但这是借用而非表示内化，依赖模型对条件的忠实响应

与透明材质调研的衔接

O-Voxel 的 6 通道 PBR 覆盖 basecolor/metallic/roughness/alpha，但未覆盖 glTF 扩展体系中的 transmission/thickness/ior 语义——因此 EditFlow3D 在 TRELLIS.2 上能稳做外观编辑，恰恰因为 PBR 先验足够强且材质分支解耦；一旦编辑超出表示范围的材质（透射/体积吸收），瓶颈不在编辑算法，而在表示层。详见本站透明材质调研报告。

💡 一句话总结：EditFlow3D 把"免训练高质量编辑数据"的成本拉到了可用线以下，使"免费后蒸馏"闭环首次可行；而材质编辑的真实边界由表示层（属性通道）划死——想突破，先扩展表示，再谈编辑。
