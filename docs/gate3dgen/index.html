「看起来更好」不等于「3D 更好」
Gate3DGen：给图生 3D 装一道"该不该修"的门

单图 3D 生成在策展基准上已经很能打，但真实照片（光照不均、模糊、前景遮挡）一进去就崩。 最自然的想法是"先用通用图像编辑修一修"，而这篇论文用数据把这个想法证伪了： 7 个主流指令编辑器全部降低 PSNR 与 SSIM，梯度 MAE 提高 17.8%–125.9%；下到 3D， 6 个能降低网格距离，但 7 个全部把两个 F1 打到比"不修"还低。 原因很直白：通用编辑为了"好看"会重画物体，而 3D 生成器恰恰是靠那些被改掉的高频明暗与轮廓线索推断形状的。 Gate3DGen 的做法是：不重训 3D 生成器，只在它前面加一道门—— 一个退化感知路由器决定"这张要不要修"，一个单步净化器在 2.3 秒内把该修的修好，且用空间损失死守身份、轮廓与纹理线索。

SECTION 01 · TAKEAWAYS

先把结论读完

共 9 条。第 1–4 条出自论文，第 5–9 条是本站读完全文（含附录与全部表格）后的判断，不是论文原话。

结论 01 · 核心实证

通用图像编辑对下游 3D 有害，这不是直觉而是数据

Table 2：7 个编辑器全部降低 PSNR 与 SSIM，梯度 MAE 提高 17.8%–125.9%，只有 FireRed 把 LPIPS 降了 0.0004（可忽略）。Table 3：6 个降低 MD，但7 个全部把两个 F1 打到未编辑输入之下。含义：去掉了大伪影，却引入了局部几何偏差。

结论 02 · 目标定义

要的是"同一物体的合适观测"，不是"更好看的图"

论文把目标精确定义为：恢复同一物体的合适观测，保留 3D 生成器用来推断形状与外观的可见结构证据。这句话是全文的锚点——它解释了为什么"看起来更干净"的编辑反而更糟。

结论 03 · 门控

干净的图不能送去净化——所以需要一个路由器

净化一个本来就干净的输入会引入不必要的改变。路由器基于 Qwen2.5-VL，用 PURIFY / KEEP 两个 token 的 logit 差经 sigmoid 得到概率，而不是 greedy 解码。合成集上 recall 88.45% / accuracy 90.77% / H 89.59%，比最强基线 MANIQA 高 5.55 点。

结论 04 · 速度与训练

一步到位：训练和推理都固定在 flow matching 的 t=1 端点

z₁ 就是纯高斯噪声，所以 一次前向 ẑ₀ = ε − v_θ(ε, E(x_o), h, 1) 再 VAE 解码即可，无需迭代去噪。这是 2.3 s 的来源（对比 FireRed 83.2 s，快 36.2×）。关键是训练也在这个端点做，不是训练多步再蒸馏。

结论 05 · 本站 · 最值得记住的一条

消融直接证明：2D 相似度不足以预测 3D 质量

Table 5 的变体 A（去掉路由器特征与空间损失）拿到最好的 2D LPIPS 0.1351 和最好的 F_all_1 12.06，却同时拿到最差的 MD 0.820 与最差的渲染 LPIPS 0.1794。论文原话："image similarity alone is insufficient to predict 3D quality"。这是本站第 4 次看到 2D/3D 指标脱钩。

结论 06 · 本站 · 论文的诚实自曝

真实照片上，路由器输给了"永远修"的平凡策略

Table 1 右半：in-the-wild H 我们 70.56%，而 DepictQA-Wild 73.68%——它的 recall 100% / accuracy 58.33%，正是"对所有输入都输出 PURIFY"。论文直言 "our router does not outperform this trivial strategy under the real-image proxy protocol"，并归因于 D_route 的 KEEP 类用的是合成干净渲染。

结论 07 · 本站 · 评测口径

in-the-wild 的路由标签是 GPT-5 打的 proxy，不是真值

真实照片没有路由标签，论文让 GPT-5 agent 通过比较多视图渲染与无参考指标来打标签。所以 Table 1 右半测的是与 proxy 的吻合度，不能读成真实正确率。同理，Table 4 的 VLM 打分用 Qwen3.8-27B 做裁判。

结论 08 · 本站 · 泛化边界

只测了 2 个 3D 生成器，且 TRELLIS.2 上的大胜没完全迁移到 Pixal3D

Table 7（Pixal3D）：我们 MD 1.091 最好、F_outer_1 0.9588 最好，但 FireRed 的 PSNR-N（10.77 vs 10.36）与 shaded LPIPS（0.2759 vs 0.2796）都更好，我们的 albedo LPIPS 只低 0.0002。论文自己也写"外观改善在 Pixal3D 上小于 TRELLIS.2"。

结论 09 · 本站 · 能力边界

遮挡能"去掉"，但被挡住的几何补不回来

论文承认：对 oracle 的残差在 F_all_1 上最大（11.96 vs oracle 12.46），因为"被遮挡隐藏的几何从单视图只能部分恢复"。所以正确的期待是：净化能移除遮挡物、避免它被融进网格，但不能凭空重建背面。

SECTION 02 · PROBLEM

难点不在"怎么修"，而在"该不该修"

论文把鲁棒单图 3D 生成重新表述为一个选择性输入净化问题——这个表述本身就是贡献。

现有输入预处理为什么不够

  • 背景移除 + 重新居中（TripoSR / InstantMesh 等开源 pipeline 常规操作）：不直接处理光度退化或前景遮挡。
  • 去光照 / delighting（SF3D、Hunyuan3D 2.5 一系）：只针对光照单一因素。
  • 核心困境：当多种退化共存时，修好一个会留下其他歧义。而通用编辑会"覆盖未损坏区域并模糊高频明暗线索"——恰恰是 3D 生成器依赖的东西。
形式化：G 是预训练生成器，x_c 是"居中、清晰、完全可见、均匀光照"的干净参考，满足 G(x_c) ≈ y；观测 x_o 可能干净也可能退化，退化会让 G(x_o) ≉ y。目标是学一个把 x_o 推向与之匹配的 x_c 的净化器。

为什么必须"选择性"

x̂_c = x_o, 若 b_γ = 0（KEEP） x̂_c = C_θ(x_o), 若 b_γ = 1（PURIFY） b_γ = 1[p ≥ τ]，p = σ(o_purify − o_keep)

两个理由逼出这道门：
① 净化一个本来就干净的输入会引入不必要的改变（论文明确列为动机）；
② 真实图像的退化是空间变化的，需要输入自身的特征来引导净化——路由器顺带提供了这个特征 h。

注意一个容易漏的设计：路由器不只是个分类器。它在触发净化时输出 final hidden states h ∈ ℝ^(N×d)，直接作为净化器的条件。门控与条件化是同一个模块的两面。
图：门控流程。虚线是"原样通过"路径，实线是"净化"路径；h 只在 PURIFY 分支中被提取并用作条件。
SECTION 03 · 数据

合成数据引擎：用 3D 资产反推出「退化 ↔ 干净」配对

真实照片既没有匹配的干净对照，也没有"该不该修"的标签。论文的解决办法是反过来造：从 3D 资产渲染干净视图，再合成退化。

步骤 1锚点视图选择

3,961 个 TexVerse 3D 资产

每个资产在均匀光照下渲染 8 个视图，由 VLM 按几何可见性与自遮挡程度排序，取信息量最大的 4 个视图作为多视图锚点，同时即匹配干净参考 x_c。

这一步决定了"干净参考"的质量——不是随便选视角。

步骤 2退化合成

复合退化，而非单一因素

对每个锚点用指令引导编辑生成匹配观测 x_o，退化包括光照不均、模糊、遮挡的组合。每对再经 Qwen3-VL 审计结构一致性，RMBG-2.0 从 x_c 提取软前景掩码 m。

代价：合成退化与真实退化的分布差距未量化。

产出两组数据 + 一个基准

训练与评测资产不相交

  • D_train：43,936 对齐图像对 (x_o, x_c, m)，供净化器
  • D_route：100k 路由对 (x, γ)，γ=1 PURIFY / γ=0 KEEP
  • 评测集：1,082 held-out DTC 案例，带 3D 真值与同相机位姿的干净参考
与本站其他页面的交叉：这里的 3D 资产来源是 TexVerse（Zhang et al., 2025）——正是本站 UltraTex 专题页所用 G-buffer TexVerse 数据集的同一来源。 同一批高质量带纹理资产，在 UltraTex 里用来训练 2048 分辨率纹理生成，在这里被反过来用作"干净真值工厂"。这是一个很经济的复用思路。
SECTION 04 · 门控 ★

退化感知路由器：两个 token 的 logit 差，顺带产出条件特征

两个细节值得学：① 用 logit 差而不是 greedy 解码得到概率；② 同一个模块兼作门控与条件提取。

为什么"无参考质量指标"做不了这件事

Table 1 给了很干脆的证据。NIQE、mPLUG-Owl2、DepictQA-Wild 的 recall 都超过 98%，但 accuracy 全都贴着 53.7%——也就是"对所有输入都输出 PURIFY"的平凡策略水平，H 只有 69.19–70.23%。

MANIQA 反过来：accuracy 89.04% 很高，recall 只有 79.57%。本文两个都要：88.45% / 90.77%。

读法提醒：这些"基线"并非同类方法——它们原本不是为 3D 生成路由设计的。Table 1 说明的是"现成的质量信号不能直接当路由器用"，而不是"本文击败了若干竞争对手"。

SECTION 05 · 净化器 ★

一步到位的净化器 + 3D 导向的空间损失

两个设计各自解决一个问题：t=1 端点解决速度，空间损失解决"修了但把物体改了"。

式 5–6把 flow matching 的训练和推理都钉在 t=1
z_t = (1 − t) z₀ + t ε 标准线性概率路径，z₀ = E(x_c) ẑ₀ = ε − v_θ( ε, E(x_o), h, 1 ) t = 1 时 z₁ = ε，纯高斯噪声 x̂_c = D( ẑ₀ ) 冻结的 VAE 解码器
为什么这一步值得单独讲：通常做法是训练多步 flow matching、再靠蒸馏压步数（会有质量损失）。 这里训练目标本身就定义在 t=1 端点——在这个点上带噪 latent 只有高斯噪声，全部图像特定信息都来自观测 latent E(x_o) 与路由器特征 h 的条件化。 速度优势（2.3 s）是训练与推理一致换来的，不是蒸馏换来的。

损失 1区域加权重建 L_region

两项独立归一化，各管一件事

L_region = ℓ(δ, m) + ℓ(δ, r) δ = x̂_c − x_c；m = 前景掩码；r = 退化图

第一项用前景掩码 m 监督整个主体；第二项用退化图 r 聚焦真正被退化影响的区域。两项各自除以自己的权重和，避免主体项被退化项稀释。

退化图 r = |x_o − x_c|/2 在 RGB 上平均后做 7×7 平均池化。

损失 2边缘损失 L_edge

直接约束"轮廓别动"

L_edge = ½ [ ℓ(D_u δ, m_u) + ℓ(D_v δ, m_v) ] D_u / D_v 为一像素前向差分；m_u / m_v 为相邻两个主体掩码值的乘积

沿水平/垂直轴匹配有限差分，权重取相邻两个主体掩码值的乘积——只有两边都在主体内时该边缘才计入，避免在物体边界外产生虚假梯度。

这条损失是"轮廓保真"的直接来源，也解释了为什么 Full 比变体 B 更能保留轮廓。

SECTION 09 · 局限

论文没有 Limitations 章节——以下 9 条由本站整理

需要说明：这篇 13 页的论文没有独立的 Limitations 章节。下列 1–3 条是论文在正文/附录中主动承认的，4–9 条是本站从实验设计中读出的边界。

边界 01 · 论文自承

真实照片上，路由器输给了平凡策略

in-the-wild H 70.56% vs DepictQA-Wild 73.68%，而后者就是"永远 PURIFY"（recall 100% / accuracy 58.33%）。原文："our router does not outperform this trivial strategy under the real-image proxy protocol"。归因：D_route 的 KEEP 类用的是合成干净渲染，与真实照片分布不同；是否加入真实照片有待验证。

边界 02 · 论文自承

FD-DINOv2 上没有任何方法超过未编辑输入

论文明确说明该指标比较的是输入与渲染的特征分布，不直接衡量退化去除或逐物体保真度，建议与 VLM 打分、人类偏好一起解读。所以 Table 4 的 FD 排名（我们 Pixal3D 第一、TRELLIS.2 第二）不应单独引用。

边界 03 · 论文自承

遮挡几何只能部分恢复

对 oracle 的残差在 F_all_1 上最大（11.96 vs 12.46），因为"被遮挡隐藏的几何从单视图只能部分恢复"。净化能移除遮挡物（避免它被融进网格），但补不回背面。

边界 04 · 本站

in-the-wild 的"标签"是 proxy，不是真值

路由标签由 GPT-5 agent 通过比较多视图渲染与无参考指标给出；VLM 打分由 Qwen3.8-27B 担任裁判。两者都不是 ground truth，且用另一个大模型评判本文方法存在系统性偏好风险。

边界 05 · 本站

只测了 2 个 3D 生成器

TRELLIS.2 与 Pixal3D。而这两个上的结果不一致：TRELLIS.2 上 MD 闭合 83.1%，Pixal3D 上只有 27.8%；Pixal3D 上渲染指标还被 FireRed 反超。对 Hunyuan3D / TripoSG / 其他生成器的迁移性完全未验证。

边界 06 · 本站

退化是合成的，分布差距未量化

观测图由指令引导编辑生成（再经 Qwen3-VL 审计结构一致性）。合成退化与真实退化的差距、以及"用编辑模型造退化、再用另一个模型修退化"是否引入系统性偏差，论文没有分析。这是合成数据方案的共性风险。

边界 07 · 本站

2.3 s 的优势主要来自"单步 vs 多步"

基线都是多步扩散编辑器。这个对比证明了单步设计可用，但若基线也做单步蒸馏，差距会显著缩小。引用时建议说"单步设计带来 2.3 s"，而非"比同类快一个数量级"。

边界 08 · 本站

VLM 与人类在"质量"上的判断不一致

VLM 给 FireRed / GPT Image-2.5 的质量分（6.92）高于我们（6.58）；而人类研究中我们对这两者的质量偏好是 63.6% / 57.5%（仍过半但明显偏低）。"资产质量"这个维度本身缺乏可靠裁判，论文坦承了两者的分歧。

边界 09 · 本站 · 定位

它是个 pre-processor，不是 3D 方法

Gate3DGen 不产出任何 3D 表示，也不改 3D 生成器。它的价值完全取决于下游模型——目前只在 2 个生成器上验证。与本站 Channel Match 专题页构成有趣对照：一个是"输入侧门控"，一个是"流水线内部 latent 校准"，都是不动下游模型的即插即用修复。

一句话总结。这篇论文的贡献不在"又训了一个图像修复模型"，而在于用一组干净的实验把"先修图再生成 3D"这个想当然的做法证伪了，并给出了替代方案。 最值得带走的是 Table 5 暴露的那件事：2D LPIPS 最好的变体，3D 网格距离最差。 这与本站此前反复观察到的现象一致——ULIP 分辨力弱（DHO / GATOR / Channel Match）、3DMM 对齐会掩盖位姿误差（Video Diffusion Avatars）—— 2D/3D 指标的脱钩已经不是个例，而是这个领域的系统性问题。任何做"图像侧改进以服务 3D"的工作，都必须在 3D 指标上验证，不能止步于图像相似度。
