UltraTex：把多视图扩散纹理生成推到 2048
先砍背景 token，再稀疏注意力，最后救回解码

UltraTex 的出发点不是"注意力太贵"这种口号，而是一笔具体的账：2048 分辨率的六视图 in-context 扩散， 输入序列长达 212,992 token，任何全注意力 DiT 都跑不动。 作者指出其中存在两类互相独立、可乘性叠加的冗余——背景导致的序列冗余（物体在画布里常常只占 5%–30%） 与前景 token 之间的注意力冗余，并分别用 Background Token Dropping（进 DiT 之前就删掉背景 token） 与 Block-Sparse Attention（保留序列上做 top-k 块选择）来消除。 第三块拼图是 Foreground-Aware VAE Decoding：推理时只对前景去噪省下了算力，却把纯高斯噪声的背景留给了 VAE 解码器， 直接解会毁掉前景——于是换成"合法背景 latent + 前景受限微调"。 配套发布 G-buffer TexVerse，351,847 个 BSDF 资产、25.3 TB。

Section 01 · Bottom Line

结论先行

如果只有三分钟，看这四张卡。

结论 01

它解决的是"能不能训"的问题，不是"好不好看"的问题

2K 六视图 in-context 扩散的序列是 212,992 token。这个数字下面，训练和推理都不可行， 所以现有方法全在 512/768。UltraTex 的三个组件本质上都是可行性工程： BTD 把序列砍到前景长度，BSA 把剩下的注意力再稀疏一层，第三块则专门为"推理时只去噪前景"这个省算力的决定擦屁股。

结论 02

最关键的一个洞察：1D 序列不必连续

作者用预训练 FLUX 做了个 probe：把 RoPE 打进初始噪声、按前景 mask 删掉背景 token， 再对这个不连续的残缺序列去噪——结果空间布局依然合理。 这说明 DiT 是靠 RoPE 读绝对坐标、而不是靠 token 相邻关系理解画布的。 所以删掉背景 token 但保留原始 RoPE 索引是安全的，多视图的极线/几何先验一并保住了。 这一条是整个方法能成立的地基。

结论 03

加速来自两级可乘叠加，且各自的主场不同

BTD 单独给出 1.4×–53.0× 训练加速（推理 1.0×–48.1×），在前景占比低时碾压——因为背景就是序列的大头； BSA 叠在 BTD 之上再给 1.7×–2.9× 训练（推理 1.6×–4.1×），且随前景占比升高而变强。 两者正好互补。最终在数据集典型区间（前景 10%–30%，ρ=20%）合计 20.6×–91.1× 训练、22.3×–74.6× 推理。

结论 04

质量提升主要来自分辨率，而非新架构

Unshaded 赛道 FID 从 LumiTex 的 147.31 降到 125.13（−15%），LPIPS 0.138 → 0.082（−41%）。 看 LPIPS 这个感知指标比看 FID 更能说明问题：差的不是分布层面，而是高频细节真的回来了。 方法上没有提新的生成范式，赢在把 2K 这条路走通了。

一句话版本：在物体中心的多视图渲染里，画布上大部分 token 根本不承载纹理信息。 UltraTex 做对了三件事——在进 DiT 之前就把它们删掉（而不是在注意力层里优化）、 删完之后再稀疏化剩下的注意力、以及补上"只去噪前景"给 VAE 解码留下的坑。 三者相乘，2K 多视图纹理生成从"不可能"变成"18 天训完"。
Section 02 · The 2K Bill

2K 走不通，是因为账单长这样

先把"212,992 token"这个数字拆开——它决定了后面每一步设计的必要性。

序列长度怎么来的

组成token 数说明
噪声目标（6 视图）6 × 16,384 = 98,3042048² → VAE 8× 下采样 → DiT 2×2 patchify
几何条件（6 视图法线）6 × 16,384 = 98,304与目标同分辨率，同样进序列
参考图16,384单张，提供外观条件
合计212,992现有方法在 512² 时只有约 13 K
换算：2048 × 2048 经 8× VAE 下采样为 256 × 256 latent，再经 2 × 2 patchify 得 128 × 128 = 16,384 token/图。 分辨率从 512 提到 2048，单图 token 数涨 16 倍，而 DiT 的注意力是 O(N²)。

但真正被浪费的部分有多大

物体中心渲染的画布里，前景占比远低于直觉。论文 Fig. 3 给了两个实例：

数据集层面的证据：G-buffer TexVerse 里 超过 85% 的资产前景占比落在 5%–30% 区间。 这不是个别样本，而是物体中心渲染的普遍性质——椅腿、人形四肢这类结构会在包围盒里留下大片空洞，裁剪也去不掉。
为什么不用现成的高效注意力方案？ 论文 §2.2 把现有工作归为一类：它们都在注意力模块内部做优化（极线对齐、Plücker 射线、代理网格对应、CTR3D 的 token 压缩）， 整条 token 序列在 DiT 主干里始终不变。当原始序列本身就超过 200 K token 时， attention 侧的节省填不上 feed-forward 和显存的坑——所以必须在进 DiT 之前就把序列缩短。这是 UltraTex 与它们的分水岭。
Section 03 · Method

三个组件：按"序列 / 注意力 / 解码"三级分层

基座是 FLUX MM-DiT + Flow Matching 的 in-context 条件范式，三个组件分别在三个层级上动手。

图 1 · UltraTex 推理链路（对应论文 Fig. 2b）。训练时（Fig. 2a）目标走 VAE Encoder，在完整 latent 网格上构造 z(t)，再施加 token-dropping mask。

3.0 基座：in-context 多视图扩散

生成器从预训练 FLUX（MM-DiT + Flow Matching）出发。参考图 Iref、多视图法线 Icond、 真值多视图 albedo Itgt 分别编码成 latent token 序列 zref / zcond / ztgt，拼接成统一序列。 Flow Matching 的数据—噪声路径与训练目标：

z(t)tgt = (1 − t) · ztgt + t · ε , t ∈ [0,1], ε ∼ 𝒩(0, I)   （式 1）
ℒFM(θ) = 𝔼 ‖ v̂θ( z(t)tgt, zref, zcond, t ) − (ε − ztgt) ‖₂²   （式 2，只对目标 token 监督速度预测）

3.1 Background Token Dropping —— 序列级

① Sequence 删掉背景，但保留 RoPE 索引

进 MM-DiT 之前一次性删除，之后所有层都直接跑在短序列上

二值前景 mask 直接从渲染数据的 alpha 通道取，下采样到 1/16 分辨率对齐 latent token 网格， 再做轻微膨胀以保留物体边界细节。六个视图的 mask 同时作用于噪声目标和几何条件 token， 参考图用自己的前景 mask。每个保留下来的 token 携带原始的 RoPE 索引。

→ 绝对空间坐标完整保留，多视图一致性所依赖的极线与几何先验不失。

Probe 支撑它的那个实验

为什么"不连续的残缺序列"还能被去噪

用预训练 FLUX 推理管线：提供六视图前景 mask → 把位置编码注入初始噪声 → 删掉全部背景 token。 结果（Fig. 4）依然产出空间合理的前景。结论是 DiT 依赖 RoPE 而非 1D 序列的连续性来理解空间布局。

→ 这解释了为什么不需要任何 token 重要性预测模块：几何 mask 已经确定性给出了答案。
ℒfgFM(θ) = 𝔼 ‖ v̂fgθ − GatherMfg( ε − ztgt ) ‖₂²   （式 3，flow matching 目标被改写为"忽略空区域"）
z(tprev)i = z(tcurr)i + (tprev − tcurr) · v̂θ,i , ∀ i ∈ Mfg   （式 4，推理时 Euler 更新只在前景位置稀疏执行）
式 4 埋下的雷：背景位置从头到尾不更新，于是采样结束时它们仍处在初始高斯噪声状态。 这就是 3.3 要解决的问题——不要急着跳过那一节。

3.2 Block-Sparse Attention —— 注意力级

② Attention 在压缩后的前景序列上做 top-k 块选择，ρ = 20%

块级打分用 mean-pool，注意力本身仍在被选中的块内做全注意力

动机来自 Fig. 5：训练一个带 BTD 的低分辨率全注意力模型后可视化其注意力图， double-stream 与 single-stream 块都呈现稀疏模式——多数前景—前景交互对局部纹理合成没有贡献。 于是把 Q、K、V 切成块（Qi ∈ ℝbq×d，Kj, Vj ∈ ℝbkv×d）：

Sc = pool(Q) · pool(K)⊤ ∈ ℝNq×Nk   （式 6，块内 mean pooling 估计块级相关性，开销极低）
Mc[i, j] = 1 ⟺ j ∈ TopK( Sc[i, :], Kρ ), Kρ = ⌊ρ · Nk⌋   （式 7，逐 query 块做行内 top-k）
Oi = Softmax( Qi KSi⊤ / √d ) · VSi   （式 8，用未池化的原始 Q/K/V 计算）
→ 压缩分数只用于决定稀疏布局；被选中的块内部仍是完整 token 级注意力，所以保真度损失可控。
ρ 怎么定的？ 在一个带 BTD 的低分辨率全注意力模型上做验证实验，权衡效率与质量：ρ 越小越快，但会丢掉重要交互导致纹理损失。 最终取 ρ = 20%——再往下压收益有限，质量风险却明显上升。
与 token pruning 系工作的区别（§2.4）：现有 token reduction 多用学习出来的重要性预测器 / 注意力分数在 Transformer 层内动态剪枝； UltraTex 用显式几何 mask 确定性识别无效 token，不引入任何新模块，且只删一次（进 MM-DiT 之前）。

3.3 Foreground-Aware VAE Decoding —— 解码级

③ Decoding 问题：纯噪声背景会毁掉前景

为保住推理加速，不能去噪背景——那就别让解码器看见它

若把"干净前景 + 纯噪声背景"的复合 latent 直接丢进标准 VAE 解码器，重建出的前景质量明显下降。 实测（Table 2）：PSNR 从全图重建的 47.65 dB 掉到 29.66 dB，LPIPS 从 0.0023 涨到 0.0263（11 倍）。

→ 这说明噪声 latent 根本不是解码器的合法输入分布。

Fix 两步：换合法背景 + 前景受限微调

不重新去噪背景，所以加速一分不丢

① 用冻结的 VAE encoder 编码一张纯黑 RGB 图得到 zbg，平铺覆盖整个 2×3 网格， 按式 9 组装复合 latent；② 冻结 encoder，只对 decoder 做轻量微调， 损失只在前台像素上计算（式 10），3,000 steps / batch 64 / lr 1e-5。

→ 最终 PSNR 50.26 dB，比"全图重建"基线还高 2.6 dB（因为监督只压在前景上）。
zmixi = zfg0,i (i ∈ Mfg) ; zbg,i (otherwise)   （式 9）
ℒdec = (1 / |Mpxfg|) · Σi ∈ Mpxfg ‖ D(zmix)i − xgti ‖₂²   （式 10，Mpxfg 为全像素分辨率下的前景 mask）
额外收益（§4.7）：前景专用去噪天然支持一个推理时的旋钮——Test-Time Foreground Scaling。 放宽 BTD 的保留范围，就能在生成时把更多 token 分配给物体前景，多视图观测里的有效纹理证据变多， 给后续重投影更多素材。这是一个不用重训就能调质量/成本权衡的开关。
Section 04 · Training Recipe

训练配方：三阶段渐进，合计 18 天

64 张 H200、per-GPU batch size 1、LoRA rank 64。这条时间线对想复现的人最有参考价值。

阶段分辨率注意力学习率步数区间耗时说明

按前景 token 数分桶

训练样本按有效前景 token 数 bucket，保证一个 data-parallel batch 内各 GPU 处理长度相近的序列， 降低负载不均。这是 BTD 的连带好处：序列长度不再由画布尺寸决定，而由物体本身决定，分桶才有意义。

显存与并行

DeepSpeed ZeRO-2 + gradient checkpointing。 论文明确点出：即便如此，前景占比超过 80% 时序列仍会超过 192 K token，所有配置全部 OOM—— 这反过来证明了"缩短序列"必须是第一步，只做注意力稀疏化救不了场。

训练数据的取用口径

G-buffer TexVerse 里只用 normal map 作为几何条件， 所有渲染视图统一 resize 到 2048 × 2048。 数据集原生最高 4096²（源纹理 ≥2048 时），训练阶段并不吃满。

FID：三条赛道全胜

同一批 100 个测试物体、32 视点。Unshaded 列缺 Step1X-3D / UniTEX（见左侧说明）。

LPIPS：差距最大在这里

LPIPS 是感知相似度，越低越接近真值。UltraTex 在 Shaded / Relighting 上比最强 baseline 低约 40%——这是 2K 分辨率带来的高频细节。

推理加速

主场是前景占比高的时候。序列越长，稀疏化能省的越多； 前景少时序列已经被 BTD 砍短，BSA 的余量就小了。

互补关系：BTD 在"背景多"时强、BSA 在"前景多"时强，两者叠加后在整个前景占比区间都拿得到可观的加速。 在数据集典型区间（10%–30%）取 ρ = 20%，合计 20.6×–91.1× 训练 / 22.3×–74.6× 端到端推理。
硬边界：前景占比超过 80% 时序列超过 192 K token，所有配置全部 OOM。 这不是参数没调好，而是说明——在高分辨率多视图扩散里，缩短序列是使能步骤，注意力稀疏化只是放大器。 顺序反了就不成立。
Section 08 · Limitations

局限：作者自己列了三条

其中两条都指向同一个根因——FLUX 这个基座本身。

局限 01

高度重复的纹理图案会失败

论文给了专门的失败案例（Fig. 11）：对重复性强的图案，生成会出问题。这一点没有给出量化范围。

局限 02

VAE latent 压缩率封住了细节上限

虽然做了前景感知的解码器微调，整条链路仍然跑在压缩后的 latent 空间里。 对高分辨率渲染真值，encode–decode 本身就会糊掉一部分高频细节。 微调解码器救不回编码器丢掉的信息。

局限 03

再往上走到 4K/8K 需要换地基

FLUX 的有效工作区间与约 1K–2K 最匹配，4K 输入已大幅超出预训练适配的分辨率范围。 作者明确说：要端到端做到 4K 甚至 8K，可能得重新设计原生支持超高分辨率输入的 DiT–VAE 基础模型。

本站补充观察：三条局限里有两条指向 latent 空间，这其实暗示了下一个可做的方向—— UltraTex 证明了token 层面的稀疏化能撑到 2K，但再往上瓶颈会转移到表示层面（VAE 压缩率与 DiT 的分辨率适配）。 另外，论文全程只用 normal map 作几何条件、输出 albedo，没有产出 roughness/metallic； 评测时 UltraTex 与无 PBR 通道的方法一样用 1/0 固定材质——所以它不是一篇 PBR 材质生成工作， 与本站 Luce 那条路线并不冲突，是互补的。
