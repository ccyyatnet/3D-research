avatar 不必是一个 3D 资产
Video Diffusion Avatars：把视频扩散模型直接调教成可控 3D 头像

主流做法两条路：3DMM 驱动 + 3DGS 渲染（显式资产），或先用扩散模型出多视图图、再蒸馏进 3DGS（CAP4D / MVP4D）。 这篇两样都不用——VDM 本身就是 avatar，全程不建任何 3D 资产，从而完整保留互联网级视频先验： 头发动力学、阴影、镜片反射与折射、随动作变形的衣物，这些显式渲染器很难做对的东西直接"继承"过来。 代价是多视图一致性必须由训练教会，而不是由表示保证。 本文最有价值的部分不在架构，而在两件事：① 用 DISTRACT 基准证明 learned 表情编码器带着严重的视角偏差（X-NeMo 视角不变性 Rank-1 仅 18%）； ② 发现 相机三元组监督本身就能涌现视角不变性（0.244 → 0.792），而单视角监督卡在 0.486。

SECTION 01 · TAKEAWAYS

先把结论读完

共 9 条。第 1–4 条是论文的核心主张，第 5–9 条是本站读完全文（含附录 Limitations、消融与实验协议）后的判断，不是论文原话。

结论 01 · 主张

不建 3D 资产，prior 才保得住

CAP4D / MVP4D 把扩散输出蒸馏进 3DGS，本质是用照片级先验换一个显式资产。VDA 反过来：视频直接由 VDM 合成，阴影、反射、折射、头发动力学全部来自 prior。代价是"多视图一致性"必须学出来，而不是由几何表示天然保证。

结论 02 · 最值钱的发现

learned 表情空间带严重视角偏差，而且它被忽视了

DISTRACT 基准：X-NeMo 视角不变性 Rank-1 只有 18%，Wan-Animate 21%，PD-FGC 甚至只有 8%；而经典 3DMM 回归器 DECA 有 61%。也就是说：表达力更强的 learned 表情空间，视角污染也更重——这是一个此前没有被量化的 trade-off。

结论 03 · 机理

表情信息没丢，只是和视角缠在一起

在同一个冻结的 X-NeMo latent 上，仅加一个 2 层 MLP probe，视角不变性 Rank-1 从 18% 跳到 98%。这说明表情信息完好保存，只是与视角纠缠——所以正确解法是显式解缠，而不是换编码器或加大容量。

结论 04 · 相机控制

表情码管不了相机：X-NeMo 分不清"转相机"和"转脖子"

论文明确写道：把 disentangle 出来的 camera latent 扫过去，动的是头而不是视点（附录 Figure 12）。所以相机与上半身姿态必须走另一条路——Plücker 着色的代理网格，且头部与躯干用各自的局部坐标系，靠颜色对比编码颈部旋转。

结论 05 · 本站 · 消融读法

三大贡献里，解缠模块的独立贡献最小

Table 5：去掉解缠但保留相机三元组，PSNR 22.06 vs full 22.43（只差 0.37 dB）；而改成单视角自驱动（self-driven）直接掉到 20.69。真正的功劳在 cross-view 三元组监督，不在解缠模块本身。论文把 disentanglement 列为支柱 (b)，消融显示它更接近"锦上添花"。

结论 06 · 本站 · 指标口径

所有像素指标都先对齐 3DMM 到真值再算

论文附录明说：为了消除歧义，先把每个方法输出的 3DMM 对齐到 GT 3DMM，再算 PSNR / LPIPS。这一步会系统性掩盖位姿误差——位姿错得多的方法在对齐后也不会被充分惩罚。所以像素指标上 22.43 vs 20.55 的差距要打折看；多视图一致性另用 3DGS 探针单测，是论文的补救设计。

结论 07 · 本站 · 静态下的优势收窄

3DGS 探针上，VDA 只比 FlexAvatar 好一点点

Table 4（静态、冻结表情）：Ours PSNR 23.69 / LPIPS 0.192，FlexAvatar 23.28 / 0.203。而 Table 2（动态自驱动）：Ours 22.43 / 0.202，FlexAvatar 20.55 / 0.327。动态场景差距远大于静态 → VDA 的优势很大一部分来自表情与动态，纯静态多视图几何一致性上优势有限。

结论 08 · 成本结构

训练极便宜，推理极贵——部署门槛在推理侧

训练 34 小时单 A100、只用公开数据（4,696 clips / 640 identities），这在同类工作里非常良心。但推理 77 帧要 12 分钟，且长序列有时间漂移；而 3DGS avatar 一旦建好就能实时渲染。论文的补救是 Self Forcing 蒸馏原型：4 步、4.8 fps @288×512，仍低于实时且画质有损。

结论 09 · 本站 · 一个被跳过的数字

对 FactorPortrait，我们的头部姿态误差更大

Table 6：Ours 在 PSNR / SSIM / LPIPS / JOD / ID / Expr 上都优于 FactorPortrait，唯独 APD（头部姿态角误差）2.94 vs 2.37 更差。论文没有讨论这一项。合理推测是对比设置对我们不利（片段由对方挑选、我们只能单目估计相机），但既然报了就该解释。

SECTION 02 · POSITIONING

三条路线的取舍：显式资产 / 蒸馏到资产 / VDM 即资产

理解 VDA 的定位，关键看清楚它放弃了什么：放弃了"渲染一次、随时复用"的显式资产，换来的是 prior 不被蒸馏损耗。

路线 A · 传统
3DMM + 3DGS/体素
LAM / FlexAvatar / UIKA。显式资产，建好可实时渲染。但 3DMM 表达力有天花板（无口腔内部、微表情丢失），阴影/反射/折射/头发动力学难以显式渲染。
路线 B · 折中
扩散 → 蒸馏进 3DGS
CAP4D / MVP4D / Joker。先让扩散模型出多视图图（或视频），再拟合 3DGS/NeRF avatar。用照片级 prior 换显式资产，蒸馏过程会损耗质量。
路线 C · 2D 化
VDM 肖像动画
LivePortrait / X-NeMo / Wan-Animate 系列。时间连贯、画质高，但没有相机控制，输出是 2D 视频不是 3D avatar。FaceCam 有相机控制但无表情控制。
本文 · 路线 D
VDM 就是 avatar
不建任何 3D 资产，直接微调 Wan-Animate-14B，让相机、表情、上半身姿态成为三个独立可控的条件。prior 完整保留；代价是多视图一致性必须被训练出来。
图：VDA 架构。表情与相机走两条互不干扰的通路，这正是本文的关键设计。
为什么必须分两条路？论文在附录给了一个很干脆的证据：把解缠出来的 camera latent 当作控制信号扫过去，转的是头而不是相机——因为 X-NeMo 的潜空间里"换相机"和"转脖子"是同一件事。 所以相机与身体姿态只能交给 Plücker 着色的代理网格（第 ⑤ 节），表情码专管表情。 来源：附录 I，原文 "X-NeMo cannot distinguish a camera change from a neck rotation, so the camera code moves the head rather than the viewpoint."
SECTION 03 · 本文新增基准 ★

DISTRACT：learned 表情空间到底有多"偏视角"

这是本文独立于架构的贡献，也是我认为最值得记住的部分。它测的问题很朴素：同一个表情从不同相机看过去，编码器给出的码还算不算同一个？

基准设计两个不变性轴 + 四类干扰项

基于 NeRSemble 的 16 相机 FLAME 跟踪序列

视角不变性（500 queries）：同身份、同序列、同帧，不同相机。身份不变性（456 组挖掘 → 人工核验保留 126 组）：不同身份的相同表情。

每个 query 配 4 类干扰项：A 同身份同相机 / B 只同身份 / C 只同相机 / D 都不同。用余弦距离排序，Rank-1 = 干扰项都没排到正样本前面的比例。

优点：直接量化"被混淆的程度"，而不是间接看下游指标。

关键结果18% → 98%：信息没丢，只是缠住了

在同一个冻结 latent 上加 2 层 MLP probe

X-NeMo 裸码视角不变性 Rank-1 仅 18%，但加一个两层的 MLP probe 后到 98%；Wan-Animate 21% → 94%；PD-FGC 8% → 90%。

结论很硬：表情信息完好保存在 latent 里，只是与视角纠缠。因此解法应是显式解缠，而不是换更大的编码器。

注意：probe 是 transductive 的（在含 benchmark 帧的 NeRSemble embedding 上拟合），测的是"latent 里含多少视角不变信息"，不代表泛化到未见身份。

SECTION 04 · 表情控制

解缠模块：把 z_raw 拆成 z_ex 与 z_cam，再把表情"翻译"回原生格式

两个设计都很克制：不归一化（norm 携带表情强度），不改动 DiT 主干（最大程度保 prior）。

式 2解缠 / 纠缠：两个 MLP head，循环重构
D(z_raw) = ( z_ex , z_cam ) ← 拆开：表情 / 相机（X-NeMo 版另有 z_id、可选的 z_res） E( z_ex , z_cam ) = ẑ_raw ≈ z_raw ← 拼回：保证没丢信息

① 有监督对比损失

标签来自多视图结构本身：同一帧的 16 个相机 = 同一表情类；相机 ID = 视角类；人物 = 身份类。三个 head 各自一个对比损失，把每个因子拉进自己的 head、把其他因子推出去。

无需任何人工标注，多视图数据天然提供监督。

② 循环一致性损失

取两个码 a、b，交换相机 latent 后穿过纠缠器再解缠，要求还原出原来的因子。这强制分解是"干净且稳定"的，而不只是能重构。

这是让 z_ex / z_cam 真正可分离的关键，光靠重构损失不够。

③ 不归一化

论文特意说明：不对 latent 做归一化，因为 norm 本身携带表情强度，必须活着走完整个往返。这是个容易被忽略但很实际的细节。

代价：下游数值尺度需要自己消化。
式 3latent 翻译：为什么要"翻译"而不是直接换码
z_ex^WAN = T( z_ex^XN ) ← MLP：X-NeMo 表情空间 → Wan-Animate 表情空间 z_raw^WAN = E^WAN( z_ex^WAN , z̄_cam^WAN ) ← 配上"视角中性"的相机码（训练集相机 latent 的均值）

两个 latent 空间毫无关系，而目标是尽量不扰动预训练权重空间，所以不能直接把 X-NeMo 码塞进 Wan-Animate。 做法是：翻译到对方的解缠表情空间，再用相机 latent 的均值（视角中性）重新纠缠回 Wan-Animate 原生格式。 这样得到的是一个"格式合法、但不含视角信息"的码。

SECTION 05 · 相机与姿态控制 ★

Plücker 着色的代理网格：用"颜色对比"把相机和脖子分开

这一节的巧思密度是全篇最高的。核心问题很具体：怎么让一张 RGB 条件图同时编码"相机在哪"和"脖子转了多少"，且两者可分离？

式 7着色公式：Lambertian 明暗 + 光线方向
c(u) = ½ · g(u) + ½ · ½ ( Rᵀ d(u) + 1 ) g = Lambertian 明暗（主光在相机上方 25°）；d(u) = 像素 u 的世界空间光线方向（Plücker 坐标的方向部分）；R = 覆盖该像素的身体部件的局部坐标系
一起变 转动脖子 → 头部颜色相对躯干单独变
图：坐标系的选择直接决定"什么信息能被写进 RGB"。本文的答案是按身体部件给各自的局部坐标系。

配套骨盆锚定的运动学拟合

解决 SAM-3D-Body 逐帧估计的抖动与漂移

多视图人脸采集里受试者是坐姿，骨盆静止。于是用一个全局相似变换 W + 每帧 MHR 关节角 ϕ_t 联合求解（Adam，400 次迭代），而不是逐帧独立对齐。

  • 骨盆漂移中位数 52–79 mm → 6–12 mm
  • 肩部游走 11.2 → 0.07 mm，帧间抖动降 14×
  • 人脸残差仅 3.04 → 3.06 mm（最多 +0.8 mm）——真实头部运动仍被跟踪，被去掉的只是坐姿受试者根本没做过的运动
验证用 NeRSemble EXP-1（头部旋转 37–56° 的大动作序列），专门用来暴露过度约束。

为什么不用 2D 骨架Wan-Animate 原生姿态信号的局限

ViTPose 2D 骨架无法迁移到新视角

Wan-Animate 原本靠 ViTPose 从 2D 预测骨架控姿态，这在 novel-view synthesis 下失效——2D 检测绑死在输入视角上。本文换成 SAM-3D-Body 的 3D 骨架，但保留 Wan-Animate 的骨架条件格式以保 prior。

消融证据（Table 5）：只给骨架、去掉代理网格 → PSNR 从 22.43 掉到 18.34（−4.1 dB），AKD 0.055 → 0.072；但 Expr 几乎不变（0.912 vs 0.920）。

说明代理网格贡献的是相机与姿态精度，不是表情保真。
SECTION 06 · 训练策略 ★

相机三元组：让"视角不变性"自己长出来

这是我最欣赏的一节——它用一个数据组织方式解决了一个看起来需要专门模块的问题，而且论文诚实报告了"解缠模块其实没那么关键"。

训练样本的构造

每个训练样本是一个相机三元组 (π_ref, π_drv, π_tar)，取自同一多视图片段的三台不同相机：

  • 参考图 I_ref 来自 π_ref（给身份）
  • 驱动片段 I_drv 来自 π_drv（给表情）
  • 目标片段 I_tar 来自 π_tar（监督重建）

关键点：因为 π_drv ≠ π_tar，表情码里携带的视角信息是"主动误导"的——训练要想把损失降下去，就只能把这个信息压掉。

这是一个用监督结构逼出不变性的设计，不是靠损失函数显式约束。它不需要额外标注，只需要多视图数据本来就有多台相机。

涌现的视角不变性（附录 Figure 14）

两组实验只差一件事：驱动表情码从哪台相机读。起点同为 0.244；cross-view 升到 0.792，self-driven 卡在 0.486，最终差 0.288。

本站判断：这篇论文最诚实的一处。论文把"解缠"列为三大支柱之一，但 Table 5 的消融显示： 去掉解缠但保留相机三元组（no disent.†）PSNR 22.06，几乎追平 full 的 22.43； 而把三元组换成单视角（self-driven†）掉到 20.69。 换句话说，三元组监督是必要条件，解缠模块是加分项。论文自己在正文也写了 "Remarkably, triplet supervision alone enforces view-invariant expression codes" —— 但标题和摘要的叙事权重并不匹配这个结论。

为什么这个探针单独存在？

因为主表的像素指标都先做了 3DMM 对齐，位姿误差被吸收掉了，无法反映"多视图是否自洽"。论文于是另设一个不需要对齐的探针。这是评测设计上的加分项。

但本站要提醒：这里 VDA 对 FlexAvatar 的优势（PSNR +0.41、LPIPS −0.011）远小于 Table 2 自驱动上的差距（+1.88、−0.125）。静态几何一致性上，VDA 只是略胜。

读法建议：VDA 的核心优势在动态与表情（以及阴影/反射/头发这些 prior 带来的效果），不是静态几何精度。别把它当"更好的 3DGS 生成器"用。

SECTION 09 · 局限与后续

论文自述的 5 条，与本站补充的 5 条

前 5 条出自第 5 节 Limitations and Future Work（含流式蒸馏原型），后 5 条是本站判断，不是论文原话。

论文原文 01

推理按片段付费，长序列会时间漂移

3DGS avatar 一旦建好可实时渲染；VDA 每一段都要跑一次 VDM 推理——77 帧 576×1024 在单 A100 上约 12 分钟。

论文原文 02

光照被烤进参考图

参考图的光照条件会被继承到生成结果中，没有显式的重光照控制。

论文原文 03

表情空间是固定的，没有端到端训练

用的是现成的 X-NeMo 编码器 + 解缠，没有把表情空间本身一起学。

论文原文 04

recipe 锚定在 Wan-Animate-14B

论文"期望"能迁移到其他 backbone，但没有验证。考虑到 861.5 M 可训练参数与特定的 face-fuser 结构，迁移成本未必低。

论文原文 05 · 已做的补救

Self Forcing 蒸馏原型：4 步、4.8 fps

蒸馏成因果四步学生（rank-128 LoRA，块因果注意力），288×512 下 4.8 fps、可稳定生成 1000+ 帧，41 秒视频约 4 分钟。代价：PSNR-F 22.43 → 21.81，JOD-F 3.99 → 3.57。仍低于实时，且训练要 60 A100 GPU 小时。

本站 06 · 叙事与消融的落差

解缠被列为支柱，消融里却是"锦上添花"

见第 ⑥ 节。去掉解缠只掉 0.37 dB，把三元组换成单视角掉 1.74 dB。论文摘要把 disentanglement 放在贡献 (b)，消融显示真正的必要条件是相机三元组监督。引用时建议这么表述。

本站 07 · 指标口径

像素指标先做 3DMM 对齐，会掩盖位姿误差

论文附录明说这是为了消除歧义，合理；但读者应知道 Table 2 的差距里已经扣掉了一部分位姿误差。真正的一致性数据在 Table 4，而那里优势小得多。

本站 08 · 基准的适用边界

DISTRACT 的 MLP probe 是 transductive 的

probe 在 NeRSemble embedding 上拟合，而这些 embedding 包含 benchmark 自身的帧。所以 98% 证明的是"latent 里有多少视角不变信息"，不是"这个 probe 能用"。论文自己点明了这一点，值得点赞，但也限制了结论的外推。

本站 09 · 部署视角

成本结构与其他路线是互补而非替代

训练 34 h/单卡很便宜，但推理 12 min/77 帧。需要实时交互的场景仍应选 3DGS avatar（FlexAvatar/UIKA）；需要最高画质 + 复杂光照/头发/反射的离线内容生产才值得付这个推理成本。论文的蒸馏原型是朝实时走的信号，但离实时还有距离。

本站 10 · 值得记一笔的透明度

伦理声明与 AI 使用声明都写得很实

论文明确：单图生成可控视频的能力可直接用于冒充与未经同意的合成媒体，且只在取得知情同意的数据集上训练（NeRSemble / AVA-256 / BecomingLit / Multiface + 公开 VFHQ）。AI 使用声明也如实披露用生成式 AI 写代码、草拟文字、生成合成参考肖像（仅用于定性示例，不参与训练与任何定量评测），并声明每个数字都对照源文件核对过。

一句话总结。VDA 的核心赌注是：与其把互联网级视频先验蒸馏进 3D 资产（必然损耗），不如直接把 VDM 变成 avatar，用条件注入换可控性。 从 Table 2 / Table 3 看，这个赌注在画质与表情保真上赢了；从 Table 4 看，它在静态多视图几何一致性上只是略胜；从成本看，它把开销从"一次性构建"转移到了"每次生成"。 而 DISTRACT 与相机三元组这两件事，价值超出这篇论文本身——任何想把 learned 表情/动作潜空间用于多视图任务的工作，都会遇到同一个视角偏差。
