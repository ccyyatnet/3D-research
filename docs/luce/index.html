Luce：把 PBR 材质写进高斯原语
可重光照的 3D 资产生成

Luce 用一组体素化多模态高斯云统一表示几何与物理材质：每个被占据的体素内，albedo、metallic-roughness、surface normal 各有一套独立的高斯原语，而非共享。 VAE 压缩成统一的 material-aware latent，rectified-flow transformer 从单图生成该 latent，解码即可直接丢进标准 PBR 渲染管线重打光。 在 Toys4K 上 FID 20.99，比最强 baseline（TRELLIS 2 的 29.22）低 28%。

Section 01 · Bottom Line

结论先行

如果只有三分钟，看这四张卡。

结论 01

它是合集中唯一「生成即 PBR」的工作

在 183 篇 6–8 月 3D 生成论文里，PBR 专题抽出 25 篇材质相关工作， 其中只有 Luce 一篇能直接产出 glTF 式的 albedo / metallic-roughness / normal 三件套。 其余要么只做逆渲染（不生成），要么把光照烘进颜色（不可重光照）。

结论 02

最大的单项增益来自一个 conditioning 改动

把 DINOv2 从单层（layer 24）换成多层拼接（layers 6/12/18/24）， Toys4K FID 从 25.21 降到 20.99（−16.7%），AI 图基准 CLIP 从 0.8081 升到 0.8519（+5.4%）。 这是全文性价比最高的一处改动——不动架构，只改条件注入。

结论 03

per-modality 解耦是「文字可读」的关键

三组高斯各有独立的位置/尺度/旋转/不透明度，可以按自身细节密度分配容量： 抛光木纹需要密集 albedo 高斯但法线平滑，拉丝金属则相反。共享一套会让三个模态互相抢原语。 这正是 Luce 能在表面上保住 logo、标签、铭文的原因。

结论 04

它没做的，恰好是透明材质调研的靶心

作者明确列出未建模的效果：subsurface scattering、anisotropy、translucency、 thin-film interference、强视角相关反射。其中 translucency 与 透明材质调研的靶心完全重合——需求侧（本页 §6）与供给侧（专题统计零覆盖）再次互证。

🎯 一句话定位：Luce 不是「生成后再逆渲染出材质」，而是把材质作为表示本身的一部分—— 高斯原语上直接参数化 PBR 三模态，所以生成出来的东西天生可重光照、天生能进生产管线。 这是它区别于 TRELLIS 2 / LiTo 的根本设计选择，而不是指标上的小幅领先。

图 1 · Luce 整体管线（对应原论文 Figure 3）。关键在 latent z 之后的分叉：GS 路径是主输出，mesh 路径是为了和 baseline 公平比较而做的适配。

3.1 多模态 PBR 高斯表示

核心设计每个体素三套独立高斯

资产是一组附着在稀疏体素上的高斯。每个被占据的体素内，三个模态 ℳ = {alb, mr, nor} 各有 K 个高斯，每个高斯带 自己的位置偏移 p、各向异性尺度 s、旋转四元数 q、不透明度 o， 外加一个与视角无关的模态值 c（albedo 为 RGB、mr 为 metallic+roughness、nor 为法线方向）。

Fi = { Gim }m∈ℳ,   Gim = { (pmij, smij, qmij, omij, cmij) }Kj=1 — 式 (2)：体素 i 内的完整表示
为什么要「独立」而不是「共享」？论文给的例子很直观：抛光木纹需要密集的 albedo 高斯去抓木纹，但法线是平滑的； 拉丝金属恰好相反——albedo 近乎均匀，metallic-roughness 和法线却要密集去抓划痕。 共享一套会强迫三个模态抢同一批原语，容量分配不由细节密度决定，而是被平均掉。
顺带推出的 K：Table 3 给出 SLatVAE 输入通道 336。 单高斯参数量 = p(3) + s(3) + q(4) + o(1) + c(3) = 14， 故 336 ÷ (3 模态 × 14) = 8 → 每体素每模态 K = 8 个高斯（论文未在正文显式给出，此为推算）。
渲染不存球谐，靠解析着色

每个模态独立做标准 3DGS alpha 合成，得到逐像素的 albedo a、metallic κ、 roughness α、法线 n、不透明度 o（法线合成后重新归一化）。 然后用 split-sum IBL + Cook–Torrance microfacet BRDF 着色：

LoIBL(ωo) ≈ [(1−κ)·a/π] · E(n) + Lpref(r, α) · [F0·A(μo,α) + B(μo,α)] — 式 (1)：漫反射辐照度项 + 预滤波镜面项
F₀ = (1−κ)·0.04 + κ·a  （标准金属工作流：介电体取 0.04，金属取 albedo 作彩色镜面）
  • 与原始 3DGS 的关键差异：不存球谐系数。视角相关的外观由 PBR 合成解析地产生，而不是靠 SH 拟合。这是「可重光照」的技术根源——SH 把光照烘进了表示，PBR 没有。
  • 法线是显式存储的，不是从形状推的。所以它可以偏离底层几何，这正是 §3.4 能做切线空间法线烘焙的前提。
  • 无需网格提取、无需 UV 展开就能着色出图。论文 Fig.10 把这套 deferred renderer 与 Blender EEVEE 做了定性对比。

3.2 SLatVAE：拿空间分辨率换每体素密度

原始多模态高斯云维度高、结构稀疏，直接上生成模型代价太大。SLatVAE 把它压成紧凑的逐体素 latent。

Encoder降分辨率

稀疏 transformer + shifted-window attention，把体素网格从分辨率 d 下采样到更粗的 d′ < d， 输出 z ∈ ℝ^(N_v^{d′³} × C)，C = 32。

Decoder提密度

在粗 latent 分辨率上运行（省算力），通过预测更多每体素高斯来补偿丢失的分辨率。 这是整个 VAE 设计里最值得抄的一条。

💡 「降分辨率 → 提密度」是一个通用的显存-细节权衡技巧。 latent 网格小 → attention 序列短 → 扩散便宜；但每个 token 携带的高斯数多 → 重建时细节不丢。 比「保持高分辨率、压缩通道」更适合稀疏 3D 结构。
训练目标渲染监督，不是 latent MSE

端到端训练，沿用 TRELLIS 的基于渲染的重建损失：解码出的高斯按模态分别可微渲染，与 GT intrinsic 图比对。

L = λℓ1·ℓ1 + λLPIPS·LPIPS + λSSIM·SSIM + λKL·KL + λvol·Lvol + λo·Lo — 附录 A：1.0 / 0.2 / 0.2 / 1e-3 / 1e4 / 1e-3
  • KL 权重只有 1e-3 —— 极弱。latent 几乎不被压向标准正态，优先保重建质量。
  • 体积正则 λvol = 1e4 —— 全文最大的系数。压制高斯尺度膨胀，防止「用大团高斯糊过去」。
  • 不透明度正则 λo = 1e-3 —— 抑制漂浮的半透明高斯（3DGS 类方法的常见伪影）。
为什么渲染监督重要：latent MSE 会让模型去拟合参数空间的数值， 但高斯参数与视觉质量之间没有单调关系（位置微调 0.01 可能视觉无损也可能崩掉）。 在渲染结果上算损失，梯度才真正对齐「人眼看到的对不对」。

3.3 Flow 生成 + 多层 DINOv2 条件注入

两阶段结构先，latent 后
  • 阶段 ① 稀疏结构生成：直接复用 TRELLIS 2 的 sparse-structure VAE 与 flow，未做任何修改。输入条件图，输出被占据的体素集合，作为下一阶段的脚手架。
  • 阶段 ② latent 生成（SLatFlow）：DiT 风格 transformer，适配稀疏 3D latent——每个样本的活跃体素构成变长 token 序列，用 flash varlen attention。时间步经 adaLN（6-way）调制，图像特征经 cross-attention 注入。时间步采样用 logit-normal(μ=1, σ=1)。
⚡ 值得注意的工程决策：结构阶段直接白嫖 TRELLIS 2。 Luce 只重训了 latent 阶段（含 VAE + flow），把「哪些体素被占据」这件事外包给现成模型。 这意味着它省掉了整整一套 64 卡 ×14 天的训练（见 §5）——把算力全部压在自己的差异化贡献上。
双解码一份 latent，两条出路

主输出是 PBR 高斯云（GS 路径，42.2 s）。为了与以 mesh 为主输出的 baseline 公平比较， 同一份 latent 也用 FlexiCubes 解码成网格——架构沿用 TRELLIS 未改，只是在 Luce 的 latent 空间上重训。

核心增益Multi-layer DINOv2

冻结的 ViT 里，浅层携带精细空间结构，深层携带语义。Luce 把多个 layer 的特征拼接后线性投影：

h = Wproj · [ fℓ₁; fℓ₂; …; fℓ_L ] + bproj,  ℓ ∈ {6, 12, 18, 24} — 式 (3)
图 2 · 多层 vs 单层 DINOv2 条件的相对改善（Table 4）。CLIP 类指标为「越高越好」的改善幅度，FID/KID 类为「越低越好」的下降幅度。 AI 生成图基准上的 CLIP 改善（+5.4%）是 Toys4K 上（+0.95%）的 5.7 倍。
🔍 这个非对称很说明问题：Toys4K 是真实玩具照片，AI 生成图基准是 130 张富含文字/logo/铭文的高细节图。 多层特征在后者上收益远大于前者，说明它补的是高频空间细节，而不是语义理解—— 深层特征已经够语义了，浅层补的是「这个字母到底长什么样」。

3.4 切线空间法线贴图烘焙

问题网格提取被体素分辨率卡住频率上限

从体素网格提取网格，几何频率的上限就是网格分辨率。亚体素的表面特征—— 雕刻、织物纹理、压印文字——在提取出的几何里根本不存在。

解法让法线高斯去学「被扰动后的有效法线」
  • 关键前提：PBR 高斯与网格是解耦的。所以可以拿施加了作者法线贴图之后的有效法线去监督法线高斯——也就是让它学一个比网格能表示的频率更细的表面朝向。
  • 推理时：把解码出的法线高斯表达在网格的局部切线坐标系里，得到 UV 参数化曲面上的切线空间法线贴图。
  • 最终网格带四张贴图：diffuse(albedo)、metallic、roughness、tangent-space normal —— 直接可导入生产渲染器。
收益零面数代价

连带收益：烘焙法线还顺带提升了颜色重建——Table 2 中 mesh color PSNR 从 31.1 升到 32.5 dB， LPIPS 从 0.091 降到 0.080。原因是着色时用了更准确的法线，漫反射与高光都更对。
🧩 这一步是把「生成模型」和「生产管线」缝合起来的地方。 纯 GS 输出虽然能重光照，但进不了 Unity/Unreal/Blender 的标准资产流程； 纯 mesh 输出又丢高频细节。Luce 用「法线高斯 → 切线空间贴图」把两者的优点合起来： 细节来自高斯，载体是标准网格 + glTF 贴图。

可抄的工程细节
  • 用 Muon 而不是 AdamW。两个 stage 都用它，lr 统一 1e-3、wd 1e-3。对 transformer 类大模型，Muon 在同等算力下收敛更快。
  • EMA decay 0.9999 —— 相当激进的平滑，配合 500K 长训练。
  • 序列长度差 20 倍：VAE 每 batch 400K voxels，Flow 8M。这正是 §3.2「降分辨率换密度」的回报——latent 网格小，才能在 8M voxels 的 batch 上跑 full attention。
  • Swin vs Full attention 按 stage 分工：VAE 需要局部性（下采样）用窗口注意力；Flow 需要全局一致（生成）用全注意力 + varlen 处理变长。
  • 数据增强细节：VAE 用随机背景（防背景泄露），Flow 用 0.5 固定背景 + 1.2 裁切 padding。
💰 复现门槛判断：43K H100 GPU-hours 属于「大厂中等规模项目」量级。 但对多数团队更有参考价值的是它的取舍策略——结构阶段白嫖现成模型、只训差异化的 latent 阶段， 相当于把预算砍掉三分之一。
Section 06 · Limitations

局限与开放问题

论文 §5 的 Limitations 写得很扎实，五条都是真问题，没有拿「future work」凑数。

L1有限分辨率体素 → 细节欠采样

表示层面的根本约束

细节尺度相对整体尺寸过小的资产会被欠采样，特征可能只跨越几个体素。作者建议的解法是级联或自适应分辨率解码：粗 latent 抓全局形状与材质结构，高分辨率阶段细化局部几何、纹理与法线。

L2材质模型只覆盖标准 PBR 属性

与本站透明材质调研直接对接

当前只建模 albedo / metallic-roughness / normal，外加 Cook–Torrance 反射模型。未建模：subsurface scattering、anisotropy、translucency、thin-film interference、强视角相关反射。作者建议扩展材质通道或学习视角相关的残差。

机会点：translucency / transmission / IOR / volume —— 四个通道在 183 篇合集中零覆盖，本论文又亲口承认未建模。

L3网格导出用的是 TRELLIS 的 FlexiCubes

架构未改，只在自己的 latent 上重训

Table 2 里 mesh 路径的耗时（79.45 s）远高于 GS 路径（0.74 s），且与 TRELLIS 2 的 88.92 s 同量级——瓶颈就在这个沿用来的网格解码器。作者把「更高分辨率或可学习的 UV-aware 提取」列为未来工作。

L4只面向物体级资产

无场景级生成

扩展到场景级需要处理光照一致性、材质一致性、物体间交互。这三条恰好是本合集里 scene 类（28 篇）在攻的问题——两条线尚未合流。

L5数据依赖：仍需多视角 PBR 渲染做监督

表示强，但喂养成本没降

每个资产的 𝒱 是在预处理阶段逐个拟合出来的：对资产做多视角 PBR 渲染，然后逐模态独立优化 K 个高斯。 这意味着 Luce 的数据管线依赖已有的 PBR 资产与其 authored 贴图（法线高斯监督的是「施加了作者法线贴图后的有效法线」）。 Toys4K 只有 412 个测试样本、PBR 子集 338 个——规模远小于 87M 级别的 Buffalo 数据引擎。 表示的上限被数据的稀缺卡住了。

对比参照：Hunyuan3D-Buffalo 1.0 §6 第 ③ 条同样把「端到端纹理编辑基本未被探索、缺训练数据」列为未解问题——两个团队从供给侧和需求侧给出了同一个诊断。
Section 07 · Takeaways

可复用的设计选择

抛开具体任务，这几条对做 3D 生成 / PBR 材质 pipeline 有直接参考价值。

1条件注入：先试试多层特征，再动架构

把 DINOv2 从最后一层换成 4 层拼接，FID −16.7%、细节图 CLIP +5.4%。零架构改动、零额外训练成本。

适用于任何「用冻结 ViT 做条件」的生成任务。如果输入侧富含文字/纹理/logo，收益会被放大——本例中细节图上的收益是普通图的 5.7 倍。

2多模态输出：解耦 > 共享

三个模态各有独立的位置/尺度/旋转/不透明度，让容量按细节密度而非平均分配。

凡是「一个网络输出多种异构目标」的场景都适用（color+depth+normal、RGB+alpha+material）。共享骨干 + 独立头是常见做法，但独立到几何参数这一层是 Luce 的关键一步。

3VAE：降分辨率、提密度、渲染监督

encoder 下采样网格，decoder 每体素预测更多高斯来补偿；损失算在渲染结果上而非 latent 上。

这条组合拳让 Luce 的 VAE 比 TRELLIS 2 快 120 倍（0.74 s vs 88.92 s）。代价是 albedo/MR 的 PSNR 低 2–4 dB——如果你的场景 VAE 要跑很多次，这个交换非常划算。

4高频细节别硬塞进几何，走法线贴图

让显式法线通道去学「被扰动后的有效法线」，推理时烘焙成切线空间贴图：+3.5 dB 法线 PSNR，多边形数不变。

这是把生成模型接入生产管线的通用接口设计——细节由连续表示承载，交付物是标准网格 + glTF 贴图。比提高网格分辨率划算得多。

5非差异化环节直接复用，把算力压在贡献点上

稀疏结构阶段直接用 TRELLIS 2 预训练权重，未修改；网格解码器沿用 TRELLIS 架构只重训。

相当于省掉一整套 64 卡 ×14 天的训练。先问「这一步我的方法真的需要不一样吗」，再决定要不要训。

6机会：透明材质是明确的空白

Luce 亲口承认 translucency / anisotropy / SSS / thin-film 未建模；183 篇合集中 transmission / IOR / volume / clearcoat / sheen / anisotropy 零覆盖。

需求侧（Apple 团队自述缺口）与供给侧（学术界无工作）已双向确认。 下一步可做的：在 Luce 的 per-modality 框架上加第四个高斯模态（如 transmission + IOR + attenuation）， 复用它现成的 VAE/Flow 骨架——这是最省力的切入点。 详见 透明材质调研 与 PBR 专题 · 空白与机会。
