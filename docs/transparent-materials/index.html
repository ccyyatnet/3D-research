Section 1 · 问题的本质

透明为什么难？两个层面

光学层面：光穿过介质同时发生折射/反射/透射/吸收/散射，严格模拟需解体积渲染方程，成本极高。渲染层面：Alpha 混合不可交换——结果依赖片元提交顺序，排序在交叉/自相交/高深度复杂度场景中要么不可行、要么开销爆炸。

维度要回答的问题代表性选择
几何表示透明体用"面"还是"体"描述？网格表面 ／ 体素/VDB ／ 隐式场（NeRF）／ 高斯基元
着色模型光在表面/体内如何散射？Alpha 混合 ／ PBR BSDF（透射/次表面）／ 体积散射
合成方式多个透明片元如何合成到像素？排序混合 ／ OIT ／ 光追累积 ／ 体渲染积分
Section 2 · 方法谱系

六类表示方法详解

从"像素级便宜近似"（A 类）到"物理级精确"（C/D 类），再到"体/神经级"（E/F 类）——每类回答的问题不同，代价也不同。

A 类 · 传统光栅化：像素级透明

A1Alpha Blending 透明混合

最基础、最通用

关闭深度写入、开启深度测试，按从远到近顺序 srcAlpha 混合。

✔ 简单、硬件级支持、可调范围大（玻璃/水/烟/粒子默认方案）
✘ 强依赖排序；不写深度导致遮挡错误；高深度复杂度下闪烁

A2Alpha Test / Masked + Dithered

透明度测试 / 裁剪（glTF 官方语义）

低于阈值的片元直接 clip；Dithered 用屏幕空间抖动图案代替混合、写深度免排序。

✔ 极廉价、正常写深度、阴影正确、无排序（树叶/栅栏/镂空）
✘ 硬锯齿、无渐变；Dithered 低分辨率有噪点需 TAA

A3Additive 加法混合

粒子专用

src + dst，数学上可交换 → 天然顺序无关。

✔ 无需排序，适合火焰/光晕/尘埃等发光粒子
✘ 只表达"叠加光"，无法表达遮挡吸收型透明（玻璃不行），易过曝

A4工程优化配套

排序加速

BSP/k-d 树加速排序；批次合批减 Draw Call；透明/不透明分队列渲染（先不透明后透明）。

✔ 低成本提升管线效率
✘ 无法根治排序依赖的结构性缺陷
📌 A 类小结：胜在简单便宜，败在"排序依赖"这一结构性缺陷，只适合低深度复杂度的场景。

B 类 · 顺序无关透明（OIT）：解决排序问题的技术谱系

OIT 不依赖输入顺序，在像素级做精确或近似的深度排序/累积。核心挑战：逐像素存储无界、带宽与内存高、锐利过渡易失真。

B1 · 精确类（Exact）

方法原理优点缺点
深度剥离 Depth Peeling每 pass 剥离一层最近深度，多 pass 逐层提取再混合精确，可作 ground truth层数越多越慢；层数受限（复杂场景穿帮）
双向深度剥离从近远两端同时剥离pass 数减半同层内多物体仍可能深度顺序错误
A-Buffer / PPL片元写入按像素组织的链表，最后排序混合精确内存不可控（无界），分配器开销大
软件光栅化精确 OIT（LucidRaster）软件光栅化做像素级精确排序~3× 硬件混合开销内做到精确实现复杂、研究前沿

B2 · 近似类（Approximate）

方法原理优点缺点
WBOIT 加权混合单 pass 累积"加权颜色+权重"，后处理一帧混合单 pass、开销低、内存小，游戏实用首选密集交叠时色彩串扰失真；权重函数需人工调参
矩基 OIT Moment-based记录深度/不透明度分布矩，矩反演重建累积透射率比 WBOIT 更准，支持较锐利过渡锐利突变仍模糊/伪影，计算较重
随机透明度每像素多层采样、随机化 alpha可恢复较高精度细节噪声大，需大量采样与 TAA
K-Buffer / MLABDB片元按深度桶分层累积，固定层数固定预算内保留强贡献层数外的信息丢失

B3神经 OIT（新方向）

前沿研究

用神经网络预测混合权重/透射率，在亿级透明基元（流场、脑神经纤维束、3DGS）可视化中与光栅化结合。

✔ 精度与开销的新平衡
✘ 尚未工程化普及

B4硬件加速现状

平台底座

Apple Metal Imageblocks 片上多层存储（官方 Demo 单 pass 多层剥离）；DX12/Vulkan 的 ROV 与 fragment shader interlock 是 A-Buffer/K-Buffer 的标准底座。

✔ 底层原语已就绪
✘ 桌面 GPU 尚无"一键 OIT"硬件，仍需引擎实现
📌 B 类小结：从"精确但贵"到"便宜但近似"构成连续谱。工程上 WBOIT 性价比最高；医疗/科学可视化倾向深度剥离；精度要求极高时改走光追（D 类）。

C 类 · 基于物理的表面材质模型（PBR / BSDF）

不纠结"排序"，从物理上把"半透明"定义为光的透射行为——区分"几何缺失型透明（Alpha）"与"实体透光型透明（Transmission）"。

C1Disney / Principled BSDF —— 全能 BSDF 中的透明建模

演进脉络：2012 年 Burley 提出 Principled BRDF（SIGGRAPH）→ 2015 年扩展为 BSDF，首次把透射与次表面散射整合进同一套参数 → 衍生实现：Blender Principled BSDF、PxrDisneyBsdf（RenderMan）、UE Glass/Translucency、Unity HDRP Lit、Cinema 4D/Octane。

能量路径模型（透明如何产生）：入射光先按 Fresnel 定律拆分：

入射光
 ├─ 反射路径：漫反射波瓣 + 镜面波瓣（GGX 微表面）+ 清漆 / Sheen
 └─ 透射路径（specTrans 控制比例）
      ├─ 薄表面：单着色点近似入射/出射散射（无内部介质，假折射）
      └─ 厚表面/体积：进入内部介质 → 吸收（Beer 定律）+ 散射（SSS/体积散射）→ 出射

透射相关参数语义（Disney/Pxr 版本）：

参数语义备注
specTrans（镜面透射）入射光中走镜面透射的比例0=全反射；1=50% 透射；2=100% 透射（0~2 区间）
diffTrans（漫透射）走漫透射的比例与 specTrans 混合构成总透射
Thin Surface是否视为无限薄薄表面时 IOR=1，不做内部折射/介质追踪
Transmission Color + Transmittance Distance体积吸收颜色与衰减距离Beer–Lambert 指数消光，模拟彩色玻璃/琥珀
Scattering Distances（RGB）次表面散射的红绿蓝平均散射距离决定"半透明质感的物理尺度"
flatness薄表面漫透射的平坦度薄表面共 13 个参数，普通表面 12 个

混合逻辑：先按 specTrans 混合 BRDF/BSDF，再按 metallic 混合金属/非金属，保证能量守恒与连续过渡。Blender 对应输入：Transmission / Transmission Roughness / IOR / Alpha（几何裁剪）/ Subsurface 三件套。

✔ 单一模型覆盖玻璃/水/皮肤/玉石/蜡，参数连续可动画；离线渲染可物理精确；资产在主流 DCC 间语义一致
✘ 参数耦合复杂、美术难直觉把控；实时引擎通常只取子集（UE 光栅化半透明不支持真实 IOR）；薄表面假折射无法表达厚体积内部光路

C2glTF 官方透明 PBR 扩展体系（跨引擎标准）

设计哲学：不把 C1 做成一个超大模型，而是拆成可独立协商、按需组合的扩展（KHR_ = Khronos Ratified）——每个扩展只加一层语义，渲染器可只实现它支持的部分（渐进增强）。

扩展关键属性物理语义典型用途
KHR_materials_transmissiontransmissionFactor / texture（R 通道）薄壁透射：光直穿无限薄表面，BTDF 为微表面镜面折射（受 roughness 控制可磨砂）；区别于 alpha——alpha 淡化整个 BRDF，transmission 仅替换透射分量、保留全强度镜面反射玻璃、透明塑料、水膜、染色布
KHR_materials_volumethicknessFactor/texture（G 通道）、attenuationDistance、attenuationColor表面升级为均匀吸收介质的边界；光在体内按 Beer 定律衰减 T(x)=attenuationColor^(x/attenuationDistance)；需流形网格；无光追引擎用 thickness 贴图做屏幕空间近似厚玻璃、宝石、琥珀、饮料（"有体积感"的透明）
KHR_materials_iorior（默认 1.5）按 Snell 定律控制折射弯曲量与 Fresnel F0；典型值 air=1.0 / water=1.33 / glass=1.5 / diamond=2.42；必须与 transmission/volume 组合才生效需真实折射的透明材质
KHR_materials_specularspecularFactor/texture（A 通道）、specularColorFactor独立于 base color 微调介质的 F0 强度与彩色镜面（F90 不随 specular 缩放以避免全反射发黑）彩色镜面高光、材质精确匹配
KHR_materials_diffuse_transmissiondiffuseTransmissionFactor/ColorFactor/Texture朗伯漫透射（无折射、无 roughness 控制）；能量守恒：给漫透射的能量从漫反射中扣减；与 transmission 并存时被镜面透射覆盖树叶、纸、灯罩、果肉、薄陶瓷、蜡

配套扩展：KHR_materials_dispersion（色散，值=20/Abbe 数，需 transmission+volume）、KHR_materials_iridescence（薄膜干涉，100~1200nm 膜厚）、KHR_materials_sss（随 diffuse_transmission 演进）。

组合规则速查（"什么时候加什么"）：

想表现的材质扩展组合说明
薄壁玻璃 / 水膜transmission +（可选 ior）无限薄、无体积衰减
厚玻璃 / 宝石 / 琥珀transmission + volume + ior（+dispersion）体积吸收 + 真折射 + 可选色散
磨砂玻璃transmission + 提高 base roughnessroughness 模糊透射波瓣
彩色玻璃volume.attenuationColor光在体内被吸收染色
树叶 / 纸 / 灯罩 / 果肉diffuse_transmission（+可选 volume 薄型）朗伯透射，不折射
皮肤 / 蜡（强散射介质）diffuse_transmission（+KHR_materials_sss）渲染器可据此切 diffusion approximation（比 random walk 快得多）

关键判据：强散射介质（σs 大）用 diffuse_transmission，弱散射透明介质用 transmission；物体大小与散射距离的相对关系决定"密度感"。

格式/标准透明语义与 glTF 扩展相比
USD UsdPreviewSurface仅 opacity 标量 + 简单 ior无法表达折射/体积衰减，透明是"淡化"而非"透射"
FBX / OBJ MTL仅 Alpha 混合/透明测试无物理透射语义，跨引擎表现差异大
NVIDIA MDL完整物理材质语言（含体积、次表面、薄膜）语义最全但生态封闭、实现重，普及度低
glTF PBR 扩展可组合、渐进增强、逐扩展协商跨引擎互操作事实标准
✔ 物理语义正确、资产一次制作全平台一致；渐进增强（不支持 volume 的引擎仍能渲染 transmission）；Three.js / Babylon.js / Filament / Blender 等广泛支持
✘ 实时引擎实现复杂：多层透射物间可见性受限；真折射需 volume 且无光追引擎只能屏幕空间近似；diffuse_transmission 目前仍为 release candidate

C2.6示例 Case：GLB 材质七属性共同作用（baseColor / normal / roughness / metallic / occlusion / transmission / thickness）

一个典型的半透明 GLB 资产，上述 7 个属性实际打包在 4 张图像里（Blender/Substance 导出惯例），采样后进入同一份 MaterialInfo，着色时分三条路径计算再合成。

a) 通道打包映射（已按 glTF 2.0 规范 + KHR 扩展核实）：

图像（GLB 内 texture）通道属性色彩空间所属
baseColorTextureRGBbaseColor（albedo / 金属反射色）sRGB核心
Aalpha（几何覆盖，可选）—核心

Bmetallic线性核心

规则：贴图采样值一律先乘对应 factor（如 roughness = roughnessFactor × tex.G）；无贴图时退化为纯 factor 值。

b) 着色管线全流程（Khronos Sample Renderer pbr.frag 流程）：

图：GLB 材质七属性共同作用流程 —— 贴图按通道采样 → MaterialInfo → 三条路径（BRDF / IBL×AO / 透射+体积）→ 最终混合

c) 关键机制要点：

  • metallic 决定 baseColor 的"解释方式"：非金属 = albedo；金属 = 镜面反射色（无漫反射项）；
  • transmission 与 alpha 的本质区别：alpha 淡化整个 BRDF；transmission 只替换透射分量，Fresnel 镜面反射始终保留；
  • thickness 必须配合 KHR_materials_volume 才生效（volume 又依赖 transmission——光要能进入体积）；无光追引擎用 thickness 贴图做屏幕空间折射近似；
  • AO 只影响间接光路径，直接光高光不受遮挡影响；
  • roughness 经 alphaRoughness = perceptual² 进入 GGX，控制高光大小与透射模糊程度（磨砂玻璃）。

d) 常见坑（实测踩坑点）：

坑现象原因
通道放错材质发黑 / 高光全无metallic 在 B、roughness 在 G、AO 在 R；P3D 系（R=metallic / G=occlusion）打包需转换
色彩空间错误亮度/颜色失真仅 baseColor 为 sRGB，其余全部 Non-Color（线性）
有 thickness 贴图但未挂 volume厚度被忽略，仍薄壁thickness 属于 KHR_materials_volume，volume 依赖 transmission
多层透射物背后透射物不可见实时引擎通用局限（官方文档标注）

C3次表面散射 SSS + C4薄膜干涉与镀膜

C3次表面散射 SSS

半透明介质的"质感动词"

光进入表面内部散射后再出射，像素尺度小于散射距离即"半透明"（玉石/皮肤/蜡/牛奶）。谱系：偶极子扩散近似 → Disney 两指数项 → 随机游走（影视级精确）→ 屏幕空间 SSS（游戏廉价近似）。

✔ 以低成本获得体积感的"透光"效果，不依赖排序
✘ 本质是近似；强光直射易过曝发灰；屏幕空间方案无法处理背面信息缺失

C4薄膜干涉与镀膜

Thin-film

多层薄膜（油膜、肥皂泡、涂层）产生波长相关的干涉色。PBR 层面多用薄膜干涉模型（如 Schlick+相位累积）或依赖光追实现；实时中常以"彩虹色"贴图/参数伪造（glTF 官方已预告对应扩展）。

📌 C 类小结：这层定义"材质是什么"，回答物理正确性问题；但渲染落地仍依赖 A/B/D 类机制（实时引擎 transmission 通常靠屏幕空间折射近似，离线/光追才真正折射）。

D 类 · 光线追踪 / 路径追踪范式

原理：沿光线递归求解折射（Snell 定律、菲涅尔、全反射），透明即"光线进入介质继续传播"——天然正确且顺序无关；配合介质跟踪可实现多层玻璃、双面折射。

✔ 物理精确（折射/内部反射/色散/体积吸收）；美术与资产层面无需排序
✘ 性能成本高；UE5 光追半透明才支持真实 IOR 与折射反弹（需双面材质 + Max Refraction Rays 配置）；光栅化半透明只能用屏幕空间假折射
📌 混合实践：游戏常用"光栅化主体 + 光追透明/反射子集"混合管线；光追半透明与 Lumen GI 等特性兼容仍有工程坑。

E 类 · 体积表示：参与介质

针对雾、烟、云、火、大气、医学体数据——透明存在于"体内"而非"面上"。

表示说明优点缺点
稠密体素 / 3D 纹理规则网格存密度/颜色采样快、可预计算光照缓存内存爆炸（VDB 469MB → 3D 纹理 3.1GB 实测），分辨率受限
OpenVDB只存"有东西"的体素，多级树结构内存降至 1/10~1/100，影视标准CPU 侧为主，GPU 需转换
NanoVDBVDB 的 GPU 版稀疏网格内存远小于稠密纹理，GPU 直接采样比 3D 纹理慢 20~30%，文档稀缺
光线步进 / Delta Tracking沿射线按步长采样，逐步累积透射率自然柔和渐变、任意形状噪声与步长选择是永恒矛盾

着色：Beer–Lambert 吸收 + 单次/多次散射 + 相位函数（Henyey–Greenstein 前向散射）；实时体积云多用半解析/分形噪声近似。适用：Houdini/Embergen 导出 VDB、科学可视化、游戏体积云/雾。

F 类 · 神经 / 学习表示（2020s 前沿）

方法透明表示方式优点缺点
NeRF隐式 MLP：位置+方向 → 密度 σ + 颜色，体渲染积分 C = Σ Tᵢαᵢcᵢ连续体、照片级新视角；半透明与反射天然一体训练/渲染慢，无法编辑
3DGS显式各向异性高斯：位置/协方差/不透明度 α/球谐颜色，按深度排序 α-混合实时（>30FPS@1080p）、训练分钟级、质量高百万级高斯存储高；半透明建模弱；透明排序又回来了
Instant-NGP / Mip-NeRF哈希网格/多分辨率编码加速训练快（秒~分钟级）仍属隐式、编辑困难
📌 F 类小结：3DGS 把"Alpha 混合 + 排序"问题带回现代实时渲染（每像素数千片元），催生了 3DGS-OIT 等专门工作；NeRF 把透明做成连续密度场，与体渲染天然契合。
Section 3 · 对比

全谱系对比矩阵

物理正确性 × 渲染性能 × 内存 × 实现复杂度 × 排序依赖，14 种表示形式一表打尽（1~5 分，5 最优/最高）。

散点图：横轴=物理正确性 ↑，纵轴=渲染性能 ↑。理想方案在右上角——目前没有；左上是 3DGS/Alpha 系（快但不物理），右下是光追/NeRF（物理但慢），B 类 OIT 与 C 类 PBR 落在中间带。

Section 4 · 决策

按应用场景的选型建议

场景推荐组合理由
移动 / Web 游戏Alpha Test + 少量排序 Blending + Additive 粒子预算最敏感，优先廉价方案
PC / 主机实时（复杂透明）光栅化主体 + WBOIT + 光追透明子集平衡质量与帧率，避免排序伪影
电商 / 产品 / 建筑可视化glTF transmission + volume + ior + 光追跨平台一致、物理正确、客户在意"真实感"
科学 / 医学可视化深度剥离（双向往返）+ 体渲染精度优先，数据不容近似错误
影视 / 离线渲染路径追踪 + Disney BSDF + VDB 体积质量天花板，不惧渲染时长
神经重建 / 实时 3D 内容3DGS（配 OIT 排序优化）/ NeRF从照片/视频重建含半透明的真实场景

趋势与展望

  1. 实时 OIT 硬件化：Metal Imageblocks、ROV/Interlock 已落地，未来桌面/移动 GPU 可能提供片上 OIT 原语，把深度剥离类方法压到单 pass。
  2. 实时光追半透明成熟：UE5/DXR 光追半透明已支持真实 IOR 与折射反弹，正逐步取代屏幕空间假折射。
  3. 神经表示倒逼 OIT：3DGS 把"百万基元 α-混合"带回实时，3DGS-OIT、神经排序等成为热点。
  4. 标准收敛：glTF PBR 扩展（transmission/volume/ior/specular/diffuse transmission + 未来的薄膜、各向异性）正在统一各引擎的透明语义，降低资产跨平台成本。
  5. 混合范式："光栅化打底 + 光追精修 + 神经补细节"的混合渲染成为工程主流，单一表示形式越来越少见。
