Part 1 · 扩展规范

五个核心扩展与组合规则

C2glTF 官方透明 PBR 扩展体系（跨引擎标准）

设计哲学：不把 C1 做成一个超大模型，而是拆成可独立协商、按需组合的扩展（KHR_ = Khronos Ratified）——每个扩展只加一层语义，渲染器可只实现它支持的部分（渐进增强）。

扩展关键属性物理语义典型用途
KHR_materials_transmissiontransmissionFactor / texture（R 通道）薄壁透射：光直穿无限薄表面，BTDF 为微表面镜面折射（受 roughness 控制可磨砂）；区别于 alpha——alpha 淡化整个 BRDF，transmission 仅替换透射分量、保留全强度镜面反射玻璃、透明塑料、水膜、染色布
KHR_materials_volumethicknessFactor/texture（G 通道）、attenuationDistance、attenuationColor表面升级为均匀吸收介质的边界；光在体内按 Beer 定律衰减 T(x)=attenuationColor^(x/attenuationDistance)；需流形网格；无光追引擎用 thickness 贴图做屏幕空间近似厚玻璃、宝石、琥珀、饮料（"有体积感"的透明）
KHR_materials_iorior（默认 1.5）按 Snell 定律控制折射弯曲量与 Fresnel F0；典型值 air=1.0 / water=1.33 / glass=1.5 / diamond=2.42；必须与 transmission/volume 组合才生效需真实折射的透明材质
KHR_materials_specularspecularFactor/texture（A 通道）、specularColorFactor独立于 base color 微调介质的 F0 强度与彩色镜面（F90 不随 specular 缩放以避免全反射发黑）彩色镜面高光、材质精确匹配
KHR_materials_diffuse_transmissiondiffuseTransmissionFactor/ColorFactor/Texture朗伯漫透射（无折射、无 roughness 控制）；能量守恒：给漫透射的能量从漫反射中扣减；与 transmission 并存时被镜面透射覆盖树叶、纸、灯罩、果肉、薄陶瓷、蜡

配套扩展：KHR_materials_dispersion（色散，值=20/Abbe 数，需 transmission+volume）、KHR_materials_iridescence（薄膜干涉，100~1200nm 膜厚）、KHR_materials_sss（随 diffuse_transmission 演进）。

组合规则速查（"什么时候加什么"）：

想表现的材质扩展组合说明
薄壁玻璃 / 水膜transmission +（可选 ior）无限薄、无体积衰减
厚玻璃 / 宝石 / 琥珀transmission + volume + ior（+dispersion）体积吸收 + 真折射 + 可选色散
磨砂玻璃transmission + 提高 base roughnessroughness 模糊透射波瓣
彩色玻璃volume.attenuationColor光在体内被吸收染色
树叶 / 纸 / 灯罩 / 果肉diffuse_transmission（+可选 volume 薄型）朗伯透射，不折射
皮肤 / 蜡（强散射介质）diffuse_transmission（+KHR_materials_sss）渲染器可据此切 diffusion approximation（比 random walk 快得多）

关键判据：强散射介质（σs 大）用 diffuse_transmission，弱散射透明介质用 transmission；物体大小与散射距离的相对关系决定"密度感"。

格式/标准透明语义与 glTF 扩展相比
USD UsdPreviewSurface仅 opacity 标量 + 简单 ior无法表达折射/体积衰减，透明是"淡化"而非"透射"
FBX / OBJ MTL仅 Alpha 混合/透明测试无物理透射语义，跨引擎表现差异大
NVIDIA MDL完整物理材质语言（含体积、次表面、薄膜）语义最全但生态封闭、实现重，普及度低
glTF PBR 扩展可组合、渐进增强、逐扩展协商跨引擎互操作事实标准
✔ 物理语义正确、资产一次制作全平台一致；渐进增强（不支持 volume 的引擎仍能渲染 transmission）；Three.js / Babylon.js / Filament / Blender 等广泛支持
✘ 实时引擎实现复杂：多层透射物间可见性受限；真折射需 volume 且无光追引擎只能屏幕空间近似；diffuse_transmission 目前仍为 release candidate

C2.1深挖：KHR_materials_volume 体积扩展

设计意图：默认 glTF 材质描述的是包裹无限薄表面（thin wall）的散射属性；volume 扩展把表面升级为"体与体之间的界面"（interface between volumes）——网格定义均匀介质的边界，提供折射、吸收效果（散射不在此扩展范围，σs=0，仅吸收）。

⚠️ 硬性约束：① 必须与允许光穿透表面的扩展组合（如 KHR_materials_transmission），否则 volume 不生效；② 体积材质要求网格封闭/流形（manifold）——薄壁可开网格，体积只能封闭网格；③ 不可与 KHR_materials_pbrSpecularGlossiness、KHR_materials_unlit 混用；④ doubleSided 属性对体积边界无效果。
① 三个属性：厚度 / 衰减距离 / 衰减色
属性默认单位/坐标语义
thicknessFactor0网格局部坐标（节点变换会作用到厚度）表面下的体积厚度；0 = 薄壁，>0 = 体积边界；范围 [0, +inf)
thicknessTexture—G 通道 [0,1]，乘以 thicknessFactor厚度烘焙图：方向与 AO 烘焙相反（沿法线反向投射射线）；暗=薄、亮=厚；有损近似——光追渲染器应忽略它、改用真实射线距离
attenuationDistance+Infinity世界空间介质密度 = 光在介质中的平均自由程；越小越"浓"（光走更短距离就被吸收）
attenuationColor[1,1,1]（白=无吸收）线性 RGB白光经过 attenuationDistance 后被吸收成的颜色（绿玻璃 = 吸收红蓝、透绿）
② Beer–Lambert 吸收模型
透射率  T(x) = attenuationColor^(x / attenuationDistance)   （x = 光在介质中行进距离）
等价（RedGPU 实现）：transmitted = base_color · exp(−attenuationColor · distance / attenuationDistance)
物理背景：衰减系数 σt = σa + σs；本扩展只定义吸收（σs = 0），σt = σa

baseColor vs attenuationColor 的本质区别（Khronos 官方图示）：baseColor 改变光穿过体积边界时的颜色——物体处处同色，像蒙了一层彩色透明箔；attenuationColor 改变光在体积内部的吸收——颜色随光路长度变化，薄处亮、厚处暗（琥珀/宝石的深度感由此而来）。

③ 与折射（IOR）的关系

光射入/射出体积边界时按 KHR_materials_ior（默认 1.5）发生折射（Snell 定律）；与 transmission 组合时用微表面折射 BTDF——roughness 同时影响反射与透射波瓣（磨砂玻璃）。介质内行进距离由入射角决定，这也是 thickness 贴图估计必然有损的原因。

④ 典型用途与引擎支持
✔ 彩色玻璃（绿/琥珀瓶）、液体（酒/带色水）、深度感宝石、厚半透明材质；引擎支持：Babylon.js / Google Filament / three.js / Substance 3D Stager / Gestaltor 等
✘ 需封闭流形网格；无光追引擎只能靠 thickness 贴图近似（有损）；多层透射物可见性受限；散射/次表面不在本扩展范围（需配合 SSS）

实践建议：thicknessFactor 常设为 mesh 包围盒最长边，贴图缩放对应各点实际厚度；烘焙厚度时射线朝法线反方向投射（类似 AO 逆向）；光追渲染时忽略厚度贴图直接积分真实距离，可保证跨渲染技术一致。

Part 2 · 实例

GLB 材质七属性共同作用

C2.6示例 Case：GLB 材质七属性共同作用（baseColor / normal / roughness / metallic / occlusion / transmission / thickness）

一个典型的半透明 GLB 资产，上述 7 个属性实际打包在 4 张图像里（Blender/Substance 导出惯例），采样后进入同一份 MaterialInfo，着色时分三条路径计算再合成。

a) 通道打包映射（已按 glTF 2.0 规范 + KHR 扩展核实）：

图像（GLB 内 texture）通道属性色彩空间所属

Aalpha（几何覆盖，可选）—核心

Bmetallic线性核心

规则：贴图采样值一律先乘对应 factor（如 roughness = roughnessFactor × tex.G）；无贴图时退化为纯 factor 值。

b) 着色管线全流程（Khronos Sample Renderer pbr.frag 流程）：

图：GLB 材质七属性共同作用流程 —— 贴图按通道采样 → MaterialInfo → 三条路径（BRDF / IBL×AO / 透射+体积）→ 最终混合

c) 关键机制要点：

  • metallic 决定 baseColor 的"解释方式"：非金属 = albedo；金属 = 镜面反射色（无漫反射项）；
  • transmission 与 alpha 的本质区别：alpha 淡化整个 BRDF；transmission 只替换透射分量，Fresnel 镜面反射始终保留；
  • thickness 必须配合 KHR_materials_volume 才生效（volume 又依赖 transmission——光要能进入体积）；无光追引擎用 thickness 贴图做屏幕空间折射近似；
  • AO 只影响间接光路径，直接光高光不受遮挡影响；
  • roughness 经 alphaRoughness = perceptual² 进入 GGX，控制高光大小与透射模糊程度（磨砂玻璃）。

d) 常见坑（实测踩坑点）：

坑现象原因
通道放错材质发黑 / 高光全无metallic 在 B、roughness 在 G、AO 在 R；P3D 系（R=metallic / G=occlusion）打包需转换
色彩空间错误亮度/颜色失真仅 baseColor 为 sRGB，其余全部 Non-Color（线性）
有 thickness 贴图但未挂 volume厚度被忽略，仍薄壁thickness 属于 KHR_materials_volume，volume 依赖 transmission
多层透射物背后透射物不可见实时引擎通用局限（官方文档标注）
Part 3 · 落地

渲染实践：透明 vs 透射

C2.7渲染实践：透明 vs 透射、alphaMode 与引擎落地

渲染器落地时最容易混淆的是"两套看穿机制"：Alpha 决定表面是否存在（像素消失），Transmission 决定光线是否穿透（表面存在但透光）——二者互不影响、可单独使用。

机制控制内容视觉效果
Alpha 透明（alphaMode）表面是否"存在"像素消失，看到背景
Transmission 透射（KHR_materials_transmission）光线是否穿透表面表面存在但透光，看到后面的物体（玻璃效果）
① alphaMode 三种模式
alphaMode行为半透明说明
OPAQUEAlpha 通道完全被忽略❌默认值
MASK二值化：alpha < cutoff → 全透明，≥ cutoff → 全不透明❌配合 alphaCutoff（默认 0.5，对应 uint8 纹理值 128）
BLEND连续混合，alpha 0~1 渐变✅支持真正的半透明，但引入排序问题

Alpha 数据来源：baseColorTexture 的 A 通道 或 baseColorFactor 第 4 分量。alphaCutoff 仅在 MASK 模式下生效。

② Transmission 与 alphaMode 的关系（Khronos 官方语义）
📖 官方 blend-mode 指引：glTF alphaMode 用于 alpha-as-coverage（表面是否存在），不是物理透射。使用 transmission 时 blend mode 应保持 OPAQUE——"表面存在但透光"与"像素消失"是两回事。规范不建议 BLEND + Transmission 混用（渲染器行为不一致）；实际使用二选一：需要"消失"效果 → 用 Alpha；需要"玻璃/透光"效果 → 用 Transmission。alpha-as-coverage 理论上可与 transmission 共存（filament / three.js 均支持）。
③ 引擎/工具落地实践
环境实践要点
Blender EEVEE（4.2+ Render Method）Dithered（延迟渲染，噪点模拟透明）= OPAQUE/MASK，兼容光线追踪与渲染通道；Blended（前向渲染真混合）= BLEND，不兼容 EEVEE 光线追踪且有排序问题
Blender 常见坑BLEND 在 Blender 中显示异常（排序/穿透）→ 方案 A 手动改 Render Method 为 Dithered；方案 B 把 alphaMode 改为 MASK（导入后自动用 Dithered）。MASK 无中间渐变；Transmission 需 Dithered 模式才能正确显示（映射到 Principled BSDF Transmission 输入）
Blender 3.6+ GLB 导出透明默认关闭：需显式启用 Export Transparent（写 Alpha 通道）+ Alpha Mode = BLEND（MASK 硬边裁剪破坏玻璃柔和衰减）+ Embed Textures（防外部 PNG 丢失）。Cycles 无法烘焙 Transmission 通道（非辐射量）；EEVEE 无折射采样，玻璃感依赖屏幕空间反射 SSR
three.jsBLEND 材质会禁用深度缓冲、无序渲染 → 树/栅栏等镂空优先 MASK（便宜且正确）；真渐变半透明才用 BLEND。运行时玻璃：MeshPhysicalMaterial 设 transmission=1.0, ior=1.5+ + physicallyCorrectLights；加载后可用 traverse 覆盖错误的 transparent 设置
Babylon.js同源问题：transparencyMode=1（ALPHATEST）可快速修复树冠等；但 glTF 是传输格式，应保证"无需本地修复"即可在任何查看器正确渲染——直接改 glTF 的 alphaMode 字段才是根治
