HKTex：会测地弯曲的高斯，因此不需要 splat
用各向异性热核彻底取消 UV 展开

3DGS 之后，很多人想把高斯搬到网格表面做纹理。HKTex 的判断是：这条路走不通，因为欧氏高斯本身不会弯—— 无论加多少正则把它们压到表面上，刚性的 3D 高斯都没法贴合流形。 作者换了个思路：不做"贴上去的高斯"，而做长在流形上的核——用黎曼几何里的各向异性热核作为测地意义上的高斯。 核的参数化、位置优化（Riemannian 梯度下降 + 动量并行传输）、自适应加密（沿主曲率方向用指数映射分裂）全部定义在曲面上。 最后接入 Mitsuba3 可微 PBR：光线打到曲面任意一点时动态求值核，而不是把它们 splat 出来。 结果是：无接缝、无畸变、无顶点复制，存储只有同质量神经表示的 1/5 – 1/10。

Section 01 · Bottom Line

结论先行

如果只有三分钟，看这四张卡。

结论 01

它不是"更好的压缩"，是"换掉参数化"

UV 的问题不在压缩率，而在参数化本身：接缝、畸变、浪费的 UV 空间、接缝线上必须复制顶点、分辨率不均。 HKTex 把纹理定义为流形上内蕴的函数，这些问题不是被缓解，而是在构造上不存在。 存储下降只是副作用——真正的卖点是"再也不用管 UV 了"。

结论 02

关键分歧点：欧氏高斯不会弯

已有工作（MeshGS、SuGaR 等）靠额外正则把高斯压到表面上，但论文认为"根本性的脱节依然存在"。 HKTex 的替代方案是把欧氏高斯换成各向异性热核——它在曲面上天然就是"测地高斯"， 各向异性（η, θ）控制的是沿曲面的扩散方向，而不是 3D 空间里的椭球。

结论 03

从不 splat，只在光线交点求值

标题里 "Do Not Splat" 是字面意思。渲染时不做光栅化，而是在光线与网格求交的连续点 p 上， 取出局部 KNN 核子集 K(p)，按式 7 的 alpha 加权单位分解算颜色。 这带来两个后果：能直接塞进 Mitsuba3 的可微光线追踪/PBR 管线；代价是求值比 splat 慢（Table 1：784.7 ms vs MLP 90.9 ms）。

结论 04

工作流是"拟合"，不是"生成"

HKTex 有两种优化入口：拟合已有 UV 纹理（当压缩器用）与从多视图图像逆向渲染（当采集工具用）。 两者都需要给定网格和相机。它不生成几何、也不从单图生成纹理—— 这与 UltraTex 那类生成式路线是完全不同的分工，不要放在一起比。

一句话版本：把"纹理"从"贴在 2D 图上的像素"重新定义为"曲面上的连续函数"， 而这个函数的基函数换成各向异性热核——它在黎曼几何里就是高斯在流形上的对应物。 于是核可以沿测地线移动（Riemannian 优化）、沿主曲率方向分裂（指数映射）、在任意连续点求值（重心插值）， 整套机制都不再需要 UV 这张平面图。
Section 02 · The UV Problem

UV 的五宗罪，和前辈们的三条弯路

先说清楚要解决的问题，否则后面那些黎曼几何工具看起来像炫技。

UV mapping 带来的固有开销

浪费空间UV 图上的空白区域也要占存储
接缝展开的切缝在着色处可见
畸变参数化无法同时保角保面积
顶点复制接缝线上的顶点必须复制一份，还得存 UV 坐标
分辨率不均同一张图上不同区域的 texel 密度不一致
一个容易被忽略的账：per-vertex 的 UV 坐标本身是固定存储开销，要计入纹理预算。 论文明确指出——对高顶点数网格，这笔开销会吃掉大部分预算， 以至于把降采样纹理压到最低 4×4 像素、ImageGS 压到只剩 10 个高斯，都仍然匹配不上 HKTex 的存储（Table 1 里 ImageGS 那一行是灾难性的）。

路线 A 隐式神经表示

MLP / InstantNGP / Intrinsic Neural Fields

用坐标网络表示外观，摆脱手工 UV。INF 甚至在数学上最贴近本文——它重心插值 LBO 的特征向量来条件化 MLP。

→ 但 MLP 求值计算重，且缺乏显式基元的局部自适应表达力；实测存储 473–928 KB，是 HKTex 的 5–10 倍。

路线 B 彩色点云 / 顶点色

存储最省，但位置由几何决定

GT VTex 只存 17.3 KB，是全场最小。但顶点的位置是几何决定的，不是纹理内容决定的—— 细分到 210 k 顶点（HR GT VTex）才勉强追上，存储反而涨到 179.6 KB。

→ 顶点是几何采样，不是自适应的纹理基元。

路线 C 3DGS 及其网格化改造

MeshGS / SuGaR / 2DGS-in-UV

3DGS revolutionised 新视角合成，但完全在环境欧氏空间运作。已有改造要么把高斯存进球面 UV 图， 要么在未展开的纹理空间里 splat，或加正则把高斯压到表面上。

→ 论文的直接批评：这些原语无法内蕴地弯曲贴合一般拓扑流形，欧氏优化天然会把高斯从几何上剥离。
HKTex 的落点：不做"贴上去的高斯"，做"长在流形上的核"。 核的各向异性控制的是沿曲面的扩散，位置更新走测地线，分裂沿主曲率方向 + 指数映射， 求值在重心插值的连续点。注意它和 INF 的关系：INF 用 LBO 特征向量喂 MLP，HKTex 用 LBO 特征函数直接构造核—— 同样是内蕴的，但保留了显式基元的局部自适应性。
Section 03 · Method

方法：从热方程到可微 PBR 的一条链

五段式：核的定义 → 谱基的参数化插值 → 连续空间求值 → 黎曼优化与密度控制 → 渲染。

图 1 · HKTex 链路（对应论文 Fig. 1 左半与 §4）。

3.1 各向异性热核：欧氏高斯在流形上的对应物

热扩散过程 L u(x, t) = ∂u/∂t 的解可写成谱形式 ut = e−tL u0 ≈ Φ e−tΛ Φ⊤ M u0（式 2）。 当初值是 Dirac delta 时就是热核——在欧氏空间中它恰好有高斯闭式解，这正是"测地高斯"说法的来源。 论文采用谱方法而非解稀疏线性系统，理由是快一个数量级且能扩展到高分辨率网格。

ht(p, p⋆ | θ, η) = Σk=1..K e−t λη,θk φη,θk(p) φη,θk(p⋆) m⋆   （式 3，截断连续各向异性热核）
h̄t(p | p⋆, θ, η) = ht(p, p⋆ | θ, η) / ht(p⋆, p⋆ | θ, η)   （式 4，除以扩散后源点温度，保证中心最高温 = 1.0）
h̃t(p) = h̄t(p) · exp( − dBH(p, p⋆)² / (2 σ²BH) )   （式 5，双调和距离高斯加权）
α(p) = [ ξ( h̃t(p) ) − ξ(0) ] / [ ξ(1) − ξ(0) ],   ξ(x) = σ( ς · (x − τ) )   （式 6，soft-step 滤波）
C(p) = cbase + [ Σs∈K(p) αs(p) cs ] / [ Σs∈K(p) αs(p) ]   （式 7，alpha 加权单位分解 + 全局基色残差）
为什么需要式 5（双调和加权）？ 热核的支撑是整个曲面；而谱截断到前 K 个频率会引入 Gibbs 类现象，在远处产生谱振铃伪影。 双调和距离高斯加权强制局部支撑、抑制远处贡献。消融里去掉它所有图像指标都变差（PSNR 45.05 → 43.99）， 这是 ablation 中掉得最狠的单组件之一。
为什么用式 6 滤波而不是优化扩散时间 t？ 固定 t，改用阈值 τ 控制尺度、锐度 ς 控制边界衰减速率。这样核既能保持渐隐外观， 也能变成边缘锐利的测地椭球，并且能缩到点尺寸。值域仍锁在 [0,1]。 附录还提到：可视化核时把 ξ 换成 boxcar 函数，就能描出空心测地椭球。

3.2 谱基的参数化插值（省掉每次特征分解）

工程关键 为每个核单独构造并特征分解 ALBO 是不可承受的

7 × 7 半极坐标网格 + 双线性插值 + 特征对齐

把 (角度 θ, 各向异性 η) 参数空间离散成网格，各向异性做对数缩放（s = ln(1+η)）使空间感知更均匀、 避免高各向异性主导。每个网格节点预计算 Φ‡i,j 与 Λ‡i,j； 查询时二分定位所在单元，按 Δθ / Δs 做双线性插值（式 8）。

但特征分解有排列 / 旋转 / 符号三重歧义，直接插值会错。论文在网格构建阶段做对齐： ① 用匈牙利算法最大化质量加权互相关 C = Φref⊤ M Φ‡ 解排列； ② 解正交 Procrustes 问题（对 Φperm⊤ M Φref 做 SVD）求旋转； ③ 用对角符号矩阵 S 修符号翻转。最终 Φaligned = Φ‡ Π R S。

→ 这个对齐步骤是形状匹配里的老问题在新场景的迁移，不做的话整个插值方案不成立。

3.3 连续空间求值：打破顶点离散化的束缚

重心插值

所有预计算谱量都定义在顶点上。为在任意连续点 p 求值，利用谱基的光滑性做重心插值 bp(A)。 这一步是"不受网格离散化约束"的前提。

双调和 KNN

对所有 S 个核、P 个点求热方程是 O(P×S)，不可行。 构造谱嵌入 Z = Φiso (Λiso)−1——在这个空间里欧氏距离恰好等于流形上的双调和距离—— 再建 KNN 图，把每个点的求值限制到 Ks = 50 个最近源。复杂度降到 O(P×Ks)。

源点质量 m⋆

连续源点处的质量不能像特征向量那样重心插值（离散质量矩阵正比于顶点面积，即局部采样密度）。 附录给了 KDE 估计（按周围点密度反比给质量，再归一化使总和 = 曲面总面积）。 但实测统一取 m⋆ = 1 更快且不掉点——因为 m⋆ 只是线性标量，其他参数能学到补偿。

3.4 黎曼优化与流形感知的密度控制

优化 核必须待在曲面上

Riemannian 梯度下降 + 动量并行传输

欧氏优化直接更新 3D 坐标必然把核拉离曲面。做法：把梯度 ∇p⋆L 投影到局部切平面 Tp⋆M 得到初速度 v⋆， 再用指数映射 Exp(p⋆, v⋆) 沿测地线求新位置。加速用的动量必须并行传输到新位置才有意义。 两者都用 straightest geodesic 算法（digeo 库，CUDA 并行）。

→ 这是"位置也是内蕴量"的直接体现：不是投到切平面再拉回，而是真的沿曲面走。

密度控制 剪枝 + 误差驱动加密

与 3DGS 同构，但分裂走指数映射

剪枝：在窗口 Δprune 内记录命中计数 ν（被选进式 7 的频率）与能量分 ω（滤波权重累计）， 淘汰 ν < γhit·max(ν) 或 ω < γenergy 的核。 加密：按局部重建误差 e(p) = ‖c(p) − cGT(p)‖₁ 加权分配给贡献核，超阈值的按空间尺度处理—— 小核（1−τ ≤ γsize）原地克隆，大核分裂成两个，沿主曲率主轴用指数映射反向位移， 新核空间范围缩小 1.6 倍，优化器状态清零（避免继承触发分裂的极端梯度）。

核会自己跑到该去的地方。论文统计：平均 49.8% 的面一个核都没有，13.2% 的面恰好一个， 而每个面上的核中心数平均 4.8 ± 7.1、最多 70 ± 123。 也就是说核的分布完全由纹理内容决定，而不是被网格顶点或 UV 图钉死——这正是顶点色方案做不到的（顶点位置由几何决定）。
Section 04 · Two Modes

两种用法：当压缩器，或当采集工具

都要给定网格（多视图模式还要相机位姿），差别只在监督信号从哪来。

模式 A · 拟合已有 UV 纹理

在 M 的面上均匀采样密集点集 p，用 C(p) 求值，与同一位置从 UV 纹理查到的真值 CGT(p) 比， 最小化 L = ‖C(p) − CGT(p)‖²₂。

  • 超参：5,000 steps，batch 4,096 点，MSE loss，初始核 1,000，t = 6.25×10⁻²，Kc = 30
  • 重要性采样：先预采 1,000 万点建池，前 250 步均匀采样做 warm-up，之后用 ε(p) 的指数滑动平均（γ=0.99）驱动采样分布偏向重建误差高的区域
  • 效果：相当于把 UV 纹理压成 96.6 KB 的内蕴表示，且解压后无接缝无畸变

模式 B · 多视图逆向渲染

给定网格 + 相机位姿，每步采样 V 个视角、找出命中网格的所有光线、随机取子集保证覆盖均匀， 最小化光线交点处的渲染误差与真值像素之差。

  • 超参：3,840 steps，batch 1,024 光线，L1 loss，初始核 5,000，t = 1.11×10⁻⁶，Kc = 20
  • 渲染：Mitsuba3 + Dr.Jit，path-replay backpropagation 积分器，训练时 ray depth 3
  • 推理优化：KNN 库与自参考热核只构建一次，显著降低开销
注意扩散时间 t 差了 5 个数量级（6.25×10⁻² vs 1.11×10⁻⁶）。这是 Optuna 贝叶斯调参在两种设置下各自搜出来的， 不是笔误——两种任务的核尺度需求完全不同。
极限测试（Fig. 4）：把一张图拟合到仅由两个三角形组成的矩形上，此时 K = 3（只有 3 个特征模态）。 HKTex 依然能表示它。这证明方法不受顶点数约束，可以表达比网格本身更高分辨率的纹理—— 这是与顶点色方案的根本分野。
Section 05 · Experiments

定量结果：存储是主指标，质量是副产品

Objaverse 严格筛选后约 3,000 个模型；UV 拟合 313 个，多视图 162 个，消融 92 个。每物体渲 5 个视角评测。

数据怎么筛的
  • 有 LVIS 类别标签、有效纹理、至少 1 个社区点赞与浏览
  • 排除点云与动画模型，顶点数上限 60,000
  • 排除多连通分量、非流形几何，以及内部结构复杂的模型（任意射线交点 > 20）
  • LBO 特征分解失败的模型直接拒掉——这是硬约束
存储怎么算的

严格计入全部内蕴参数、网络权重，以及 baseline 所需的拓扑开销（如 UV 坐标）。 统一格式、不做方法专属量化、统一 zip 压缩。 所以 UV 类 baseline 的那笔 per-vertex UV 坐标开销是算进去的——这是公平的。

实现栈

PyTorch + FAISS（GPU 版）做双调和 KNN + Mitsuba3 / Dr.Jit 可微光追。 不写专用 CUDA kernel，改用 PyTorch Triton 代码生成。 各向同性 LBO 预计算 64 维，ALBO 网格（7×7）每个 256 维。

存储 vs 质量：柱是存储，线是 PSNR

柱子越矮越好（存储 KB），折线越高越好（PSNR）。HKTex 用 96.6 KB 拿到接近 HR GT VTex（179.6 KB）的 PSNR，而神经方法要 473–928 KB。

怎么读这张表

  • LR GT UV 的 48.4 dB 是"作弊"基线——它直接存图像样本，PSNR 天然最高，但 LPIPS 2.3 并不好，且占地 115.8 KB。它不是公平对手。
  • 真正的对照是神经三兄弟（MLP / InstantNGP / INFs）：HKTex 存储只要它们的 1/5 – 1/10，却在 LPIPS、SSIM、MS-SSIM、MSE 四项上全面更好。
  • SSIM 98.9 / MS-SSIM 99.5 是全场最高，MSE 0.08 与 HR GT VTex 并列最低——结构细节保得最好。
  • ImageGS 的 MSE 3.65±11.95 崩了：存储预算被 UV 坐标开销吃掉，只剩 10 个高斯可用。
  • Render 784.7 ms 是全场最慢（约 8.6 倍于 MLP 的 90.9 ms）——这是"不 splat"的代价，见 ⑦。

柱 = 存储 KB（越低越好），线 = LPIPS×10⁻²（越低越好）。HKTex 两项都最低。

三条值得记住的结论

  • 驱动质量的是自适应插入，不是剪枝。去掉 error-based densification 立刻掉 2.00 dB， 而去掉 pruning 基本没变化（45.05 → 45.06）。作者的解释：误差驱动加密 + 流形感知分裂本身已经提供了足够自适应性，剪枝只是省算力和存储。
  • 双调和加权不能省。去掉它所有指标都变差（PSNR −1.06），印证了它在抑制长程谱振铃、强制局部支撑上的作用。
  • 重要性采样影响的是 MSE 而不是 PSNR。去掉后 PSNR 反而略升（45.13），但 MSE 从 0.058 飙到 0.691（12 倍）。 解读：均匀采样在容易的区域过拟合，而没能把难的高频区域一致地解出来。只看 PSNR 会误判。
Section 07 · The Cost

代价：不 splat 就要在交点求值

这是论文自己坦白的开销，也是落地前必须知道的。

渲染耗时

场景HKTex最快 baseline倍数
UV 拟合（Table 1）784.7 ± 474.3 msHR GT VTex 50.3 ms15.6×
多视图（Table 2）1.2 ± 0.37 sHR VTex 0.58 s2.1×

原因有两个：核聚合（KNN 查询 + 谱求值）与测地邻域查询。 论文指出多视图场景里这个开销被部分摊薄——因为 ray depth 增加后，光线追踪本身主导了渲染时间。

前处理依赖

  • LBO 特征分解是硬前提。分解失败的模型直接被数据集拒掉。附录提到 K = 256 经验上够用； K 减小会让核变大，但可学习的 τ 能补偿。
  • ALBO 网格要预计算 49 组 256 维特征分解（7 角度 × 7 各向异性），还要做特征对齐（匈牙利 + Procrustes）。这是每个网格的一次性成本。
  • 几何筛选很严：非流形、多连通分量、复杂内部结构都不行。论文说标准可以放宽，代价是数据质量下降或需要分块处理。
  • 依赖 digeo 库做指数映射与并行传输（CUDA 并行实现），这是 Riemannian 优化能跑起来的前提。
怎么看待这个开销：HKTex 换来的是存储省 5–10 倍 + 无接缝无畸变， 付的是渲染慢 2–16 倍 + 每个网格的一次性谱预计算。 这个交换在存储/传输受限、渲染离线的场景（游戏资产分发、AR/VR 内容、VFX）非常划算； 在实时渲染场景则明显不成立。论文没有做实时化尝试。
Section 08 · Limitations

局限：作者明说的与没说的

局限 01（作者）

目前只有 albedo

论文明确 "without loss of generality, we focus this study on albedo texture properties"。 未来工作说每个核可以再挂 roughness / specular 等材质参数并用 Mitsuba3 可微渲染优化—— 但本文没做，所以它不是 PBR 材质表示（至少现在不是）。

局限 02（附录）

编辑性不友好

附录直言"直接编辑并不简单"（这个局限与 GS 共有，球谐还会加剧）。 可行路径是：把目标区域烘焙成稠密点云 → 绘制 → 跑一小段优化把改动传回 HKTex 参数。 没有交互式编辑能力。

局限 03（附录）

transmission 还没解决

附录有一句"完全消除对 transmission 的需求……留待未来研究"。 也就是说半透明相关的渲染路径目前仍依赖 transmission，且作者没把它纳入本次方案。

本站补充观察（论文未明说）： ① 它需要网格——两种模式都以"给定网格"为前提，不能像生成式方法那样从图像造纹理， 所以它是资产管线的一环，不是端到端生成器。 ② 优化是 per-object 的：每个物体跑 3,840–5,000 步优化，没有跨物体共享的先验—— 这也是它能压到几十 KB 的原因（过拟合到单个物体），但也意味着每个资产都要单独优化一遍。 ③ 它和测地热扩散的前作（Foti et al., NeurIPS 2024）一脉相承，本文的进步在于各向异性核 + 完整密度控制 + PBR 集成。 ④ 与本站 透明材质调研 的关系：热核天然只处理表面内蕴属性， 体散射 / 透明不在这个表示的能力范围内。
Section 09 · Positioning

它在本站纹理路线图里的位置

9 月的纹理方向有三条线并行，HKTex 是"取消 UV"那条。

路线代表工作输入产出本站页面
取消 UVHKTex（本篇）网格（+ 可选 UV 纹理 / 多视图图）内蕴热核纹理，无接缝无畸变，几十 KB本页
把分辨率拉满UltraTex参考图 + 几何法线2048² 多视图 albedo，重投影到网格UltraTex 解读
直接生成 PBRLuce / GS-PI单图 / 点云albedo + metallic-roughness + normalLuce 解读
三者不冲突，且理论上可以串起来：UltraTex 这类生成模型产出的是多视图 albedo 图， 而 HKTex 的第二种模式正好就是从多视图图拟合纹理—— 用生成结果替换掉真值渲染图喂给 HKTex，就能得到"无需 UV 展开、几十 KB、无接缝"的最终资产。 论文没有做这个组合实验，但接口是对得上的。
